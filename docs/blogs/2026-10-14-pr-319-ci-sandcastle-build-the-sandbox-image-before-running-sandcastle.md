# ci(sandcastle): Build the sandbox image before running Sandcastle

- **Release tag:** `v0.0.140`
- **Source PR:** [#319](https://github.com/mpaulosky/Blazor-Server/pull/319)

## PR description

### Why

The first automatic Sandcastle runs, started by labelling the UI restyle issues (#311 to #317), did no work. Every intake attempt failed with
`Provider 'docker' create failed: Image 'sandcastle:blazor-server' not found locally. Build it first with 'sandcastle docker build-image'.`
A hosted runner starts with no images, and nothing in the workflow or the host builds one. Locally the image already existed, so this only showed on GitHub Actions.

### What changed

- **`.github/workflows/sandcastle.yml`** gains a **Build the sandbox image** step after the dependency install: `pnpm exec sandcastle docker build-image`.
  - With no flags it builds `.sandcastle/Dockerfile` and names the image after the checkout's folder, the same rule the host uses to look it up.
    On the runner that's `sandcastle:blazor-server`, the name in the error.
  - It runs on every triggered run, including runs with no work, so those now take as long as a Docker build.
- **`docs/plans/sandcastle-workflow.md`:**
  - The **Trigger and run environment** section lists the new step.
  - The **Early exit** section no longer says the host checks for work before the image is built.

### Verification

- Ran `pnpm exec sandcastle docker build-image` in a checkout. It built `.sandcastle/Dockerfile` as <code>sandcastle&#58;&#60;folder&#62;</code>, matching the host's `defaultImageName`.
- The pre-push gate passed (actionlint, zizmor, markdownlint, build and tests).
- The real check is the next run on Actions after this merges: intake should judge #311 to #317 instead of failing on the image.

Not fixed here: a run whose intake fails on every issue still ends green. That's host code in `.sandcastle/`, and it needs its own issue.
