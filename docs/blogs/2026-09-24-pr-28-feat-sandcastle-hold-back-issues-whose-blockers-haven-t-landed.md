## feat(sandcastle): Hold back issues whose blockers haven't landed

- **Release tag:** `v0.0.32`
- **Source PR:** [#28](https://github.com/mpaulosky/Blazor-Server/pull/28)

### PR description

## Summary

The planner inferred dependencies from issue prose alone, so it could start an issue whose explicit blocker was still open (e.g. #23, which is blocked by #22). This adds a host-side **blocker gate** (Phase 0) that runs before planning each round.

## Changes

- **Gate (`.sandcastle/main.mts`).** For each open `Sandcastle` issue, collect blockers from GitHub's native "blocked by" links and from body lines starting with `Blocked by #N` / `Depends on #N` (prose mentions such as "reuses the generator from #22" don't count). A blocker has landed only when it's a merged PR or an issue closed as completed. An open blocker, one closed as not planned or duplicate, or a PR closed without merging keeps the issue held back, and the reason is logged.
- **Planner only sees ready issues.** `plan-prompt.md` now receives the gated list via `{{ISSUES_JSON}}` instead of running `gh issue list` itself. The plan is also filtered against the gate in code, so a stale or invented id can't start blocked work.
- **Resilient lookups.** A blocker that can't be fetched (mistyped number → 404, network error), or an issue whose native links can't be read, holds back only that issue instead of aborting the run.
- Blockers are re-resolved every round, so an issue unblocks as soon as its blocker's PR merges.
- **Tooling.** `markdownlint-cli2` is now a local dev dependency, so the pre-commit hook finds `node_modules/.bin/markdownlint-cli2` and the pre-push hook's `npx` call uses the local copy.

## Security

Issue bodies are untrusted and now flow into a prompt template that supports ``!`cmd` `` shell expansion. Checked in `@ai-hero/sandcastle` 0.12.0: `substitutePromptArgs` marks the template's own shell blocks *before* substitution and strips the marker from argument values, and `preprocessPrompt` only runs marked blocks. So shell syntax inside an issue body is never executed. Substitution is single-pass, so `{{…}}` in issue text isn't expanded either.

## Known limitations (follow-ups)

- Formats not recognised: `> Blocked by #7`, `1. Depends on #10`, `- [ ] Blocked by #8`, and full issue URLs.
- The blocker cache is keyed by number only, so a native blocker in another repo could shadow a local issue with the same number.
- A blocker closed as duplicate blocks forever until the dependent issue is edited.
