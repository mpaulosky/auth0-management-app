# docs(claude): Add Sandcastle and Baseline rules for agents

- **Release tag:** `v0.0.97`
- **Source PR:** [#207](https://github.com/mpaulosky/Blazor-Server/pull/207)

## PR description

### Why

Sandcastle's agents load `CLAUDE.md` and the path-scoped rules in `.claude/rules/`. Two kinds of work had no rule:

- **Sandcastle itself.** Every open Sandcastle issue changes the TypeScript in `.sandcastle/`, but
  `docs/CODING_STANDARDS.md` covers only C#. Its conventions (style, comments, how dependencies are injected, how tests
  are written) and its host-safety guardrails were written down only in code comments. The guardrails matter most:
  #194 happened because a change that weakened nothing on paper broke every run, and the stubbed tests couldn't see it.
- **The Baseline's CI files.** `CLAUDE.md` says `scripts/gate.sh` is overwritten on every Apply, but nothing said which
  other files the repo-ci-baseline Template owns. An agent could edit a workflow or a hook, and the next Apply would
  silently undo it.

### What changed

- New `.claude/rules/sandcastle.md`, which loads for `.sandcastle/**`, `package.json` and the pnpm lockfile:
  - **Code:** the module style; comments that explain why; the outside world injected through host objects or
    parameters with live defaults; dependencies kept to what's there; failing closed.
  - **Tests:** `node:test` with `node:assert/strict`, stubs as plain objects, and tests named for the behaviour they
    pin.
  - **Host safety:** the guardrails a change has to keep. A change to mounts, the sandbox provider or how the host runs
    git must say in its commit and PR that it needs a run against a real sandbox before merging. That's the check that
    would have caught #194.
- New `.claude/rules/baseline.md`, which loads for `.github/**`, `scripts/**` and the other files the Template supplies:
  - It explains Owned files (overwritten on every Apply) and Seed files (the repository's own), and lists each kind.
  - It says where repo-only changes go instead (`.github/ci/gate-checks.sh`, `.github/ci/prepare.sh`).
  - When a task needs an Owned file changed, the agent writes the exact change under **Baseline change needed** rather
    than editing a file the next Apply would overwrite.
- `CLAUDE.md` names the two new rule topics.

### Verification

- `markdownlint-cli2` passes on all three files, and the pre-push gate passed.
- The Owned and Seed lists are from the Template's `template/owned/` and `template/seed/`. The code references
  (`BuildHost`, `SandboxHost`, `publish`, `publicErrorText`, `lib/scan.mts`, the token check in `main.mts`) were checked
  against `main`.
