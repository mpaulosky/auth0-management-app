# feat(ui): Show the Release and commit in the footer

- **Release tag:** `v0.0.155`
- **Source PR:** [#361](https://github.com/mpaulosky/Blazor-Server/pull/361)

## PR description

Closes #349

### Why

The Generated App's footer showed only the app name and the copyright line, so a visitor or maintainer looking at a running build had no way to tell which Release or commit it was built from.
The prerequisite change (#350) stamped that information into a `BuildInfo` singleton at build time; this change puts it on screen.

### What changed

- `Footer.razor` injects `BuildInfo` and adds a Release item and a Last Commit item after the existing app name and "Built with" line, which are unchanged.
- The Release item shows the Release label, linking to <code>&#123;repo&#125;&#47;releases&#47;tag&#47;&#123;tag&#125;</code> when a tag is known, or `no release` linking to <code>&#123;repo&#125;&#47;releases</code> when it isn't.
- The Last Commit item shows the commit's first 7 characters, linking to <code>&#123;repo&#125;&#47;commit&#47;&#123;full sha&#125;</code>.
  It's hidden when the build has no commit.
- Both items render as plain text, with no link, when the repository URL is empty or isn't `https://` (an `http://` or SSH remote, for example).
  Links open in a new tab with `rel="noopener noreferrer"` and use the `accent-*` colours with `dark:` variants, not a raw hue.
- A new internal `RepositoryLink.BaseFrom` strips a trailing `/` and `.git` from the repository URL and returns empty for anything that isn't `https://`.
  `ReleaseLabel.FromDescribe` now uses it, so a non-`https` URL leaves the Release link empty too; before, only an empty URL did.
- A new `CommitLabel` record, beside `ReleaseLabel`, builds the short commit and its link. A commit shorter than 7 characters is shown whole.
- The footer renders both items' link-or-text fallback through one `LinkOrText` helper, the same idiom `NavMenu.razor` uses, so the two can't drift apart.

No design note was written for this issue.

### Verification

- `tests/UI.Tests.Unit/Components/Layout/FooterTests.cs` (bUnit, with a supplied `BuildInfo`) pins the Release link for a known tag and for `no release`,
  the 7-character commit link to the full SHA, the hidden Last Commit item when there's no commit, no <code>&#60;a&#62;</code> at all with an empty or non-`https` repository URL,
  links without a trailing `.git` or `/`, and `target="_blank"` with `rel="noopener noreferrer"` on every link.
  Its two existing tests (app name, year from `TimeProvider`) keep their assertions and now register an empty `BuildInfo`.
- `tests/UI.Tests.Unit/Components/Layout/CommitLabelTests.cs` pins the short commit and its link for `https` URLs with and without a trailing `.git` or `/`,
  no link for an empty, `http://` or SSH URL, and an empty or short commit returned as is.
- `tests/UI.Tests.Unit/Components/Layout/ReleaseLabelTests.cs` adds cases for no link with an `http://` or SSH URL and for stripping a trailing `/`.
- `tests/UI.Tests.Unit/Components/Layout/MainLayoutTests.cs` registers an empty `BuildInfo`, since the layout renders the footer.
- The acceptance tests were committed failing first, and pass unchanged.
- `scripts/gate.sh` passed on the final commit: the lints, the Release build, and every test project, including `UI.Tests.E2E` through the AppHost
  (7 passed, plus 1 skipped that needs a reachable Auth0 tenant).
