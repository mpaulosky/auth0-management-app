# feat(ui): Tint the surfaces with the Palette, and guard them

- **Release tag:** `v0.0.164`
- **Source PR:** [#392](https://github.com/mpaulosky/Blazor-Server/pull/392)

## PR description

Closes #388

### Why

The Palette only changed the accent colour, which covers buttons, links and highlights.
Every page, card, nav bar, footer, border and hover fill stayed slate whichever hue the visitor picked, so a Generated App looked nearly the same in every Palette.
This branch applies [docs/plans/palette-tint.md](docs/plans/palette-tint.md) so the Palette tints the surfaces too, in both Themes.
Two text and focus-ring shades change with it, because the old ones fail WCAG AA on the tinted surfaces.
An architecture test now fails the build if a slate surface class comes back.

### What changed

- In every `.razor` file under `src/UI`, each `slate-*` background, border, divider and gradient stop moves to the matching `accent-*` class from the spec's table.
  This covers `App`, `MainLayout`, `NavMenu`, `Footer`, `ReconnectModal`, `LoginDisplay`, `ThemeControl`, `Badge`, `Button`, `Card`, `StatTile` and `ProfilePage`.
  The page is `bg-accent-100 dark:bg-accent-950`.
  Cards, the nav and the footer keep `bg-white/80` (or `/70`) in Light and use `dark:bg-accent-900/*` in Dark.
  Hover fills are `hover:bg-accent-200 dark:hover:bg-accent-800`, and the Profile rows are `even:bg-accent-50 dark:even:bg-accent-950/30`.
- Secondary text moves from `text-slate-500` to `text-slate-600` in Light and from `dark:text-slate-400` to `dark:text-slate-300` in Dark.
  Every `focus-visible:outline-accent-500` gains `dark:focus-visible:outline-accent-300` next to it.
- In `PaletteMenu.razor`, only the <code>&#60;summary&#62;</code> follows the table.
  The panel, the tiles and the current swatch's ring stay slate so each swatch shows its true hue, and a comment above the panel explains why.
  The <code>&#60;summary&#62;</code> also lost its `text-slate-600 dark:text-slate-300`, so its `▾` takes the page's body text colour, like the Log in pill.
  The spec only bars slate backgrounds and borders on it, but the new bUnit test bars every `slate-` class.
- The spec has no table row for `StatTile` or the Profile table header, and leaves their final styling to issue #389.
  For now both move from `bg-slate-50` to `bg-accent-100` by the same substitution as the page.
- The amber error banner and the coloured Badge tones keep their hue, because their colour carries meaning.
- `README.md` says the Palette tints the accent and the surfaces, and that the Palette menu's panel stays slate.
- No design note existed for this issue.

### Verification

- `tests/Architecture.Tests/UiRestyleTests.cs` now checks every `.razor` file under `src/UI`, not four layout files. Its checks:
  - no `gray-` or `blue-` class;
  - no `bg-`, `border-`, `divide-`, `ring-`, `from-`, `via-` or `to-slate-*` class, with or without a variant prefix, in any file except `PaletteMenu.razor`;
  - no `text-slate-500` or `dark:text-slate-400`;
  - every quoted class string that contains `focus-visible:outline-accent-500` also contains `dark:focus-visible:outline-accent-300`.
  The tests went red against the old markup first.
  Putting `bg-slate-50` back on <code>&#60;body&#62;</code> makes the slate check fail.
- `tests/UI.Tests.Integration/AppTests.cs` checks that <code>&#60;body&#62;</code> and `MainLayout`'s root <code>&#60;div&#62;</code> render `bg-accent-100` and `dark:bg-accent-950`.
  It also checks that the compiled CSS has the `dark:bg-accent-950` rule for an explicit Dark Theme and for System.
- `tests/UI.Tests.Unit/Components/Features/Palettes/PaletteMenuTests.cs` checks that the panel keeps `bg-white` and `dark:bg-slate-900`.
  It also checks that the <code>&#60;summary&#62;</code> has `border-accent-200` and `dark:border-accent-700` and no `slate-` class.
- `HomePageTests`, `ButtonTests` and `ReconnectModalTests` now expect the `accent-*` border, background and backdrop classes where they used to expect slate.
- `tests/UI.Tests.E2E/PaletteTests.cs` picks Rose in a real browser and waits for <code>&#60;body&#62;</code>'s computed `background-color` to change from Blue's.
- `scripts/gate.sh` passed: Markdown lint, a Release build, and every test project.
  Architecture ran 105 tests, Domain 30, UI unit 381, UI integration 89 and AppHost integration 5.
  The E2E run had 11 tests pass and 1 skip, which needs a reachable Auth0 tenant.
