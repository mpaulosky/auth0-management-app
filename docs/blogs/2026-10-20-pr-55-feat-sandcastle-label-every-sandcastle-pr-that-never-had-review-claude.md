# feat(sandcastle): Label every Sandcastle PR that never had review:claude

- **Release tag:** `v0.0.16`
- **Source PR:** [#55](https://github.com/mpaulosky/auth0-management-app/pull/55)

## PR description

Closes #51

### Why

Claude reviews a pull request only when it carries the `review:claude` label. Sandcastle adds that label to each PR it opens, but two kinds of Sandcastle PR could still go without it.
The first is a PR whose run stopped between creating the PR and labelling it, through a job timeout, a cancellation or a crash.
No later run labels it, because the gate holds back any issue that already has an open PR.
The second is any Sandcastle PR that was already open before Sandcastle started labelling its PRs.
A failed label add was listed in the run report, but the run still ended green. Sandcastle publishes with the owner's token, so GitHub notified nobody.
And if someone deleted the `review:claude` label from the repository, every label add in a run would fail.

### What changed

- The follow-up sweep now adds `review:claude` to each Sandcastle PR it sweeps that doesn't carry the label and has never carried it. It reads the PR's label events to decide.
  A PR that carried the label before is left alone, so PR Auto-Merge's review cap still holds.
- The "has this PR ever carried `review:claude`?" check is now `hasCarriedReviewLabel` in `.sandcastle/lib/github.mts`. Both `openPullRequest` and the sweep call it.
- If the sweep fails to add the label, it logs a warning and lists the PR under **Pull requests without `review:claude`** in the run report.
  If it fails to read a PR's label events, it only logs a warning. It doesn't list the PR, because telling the owner to add the label by hand to a PR the review cap unlabelled would bypass the cap.
  Either way it goes on to follow the PR up and to sweep the next one, and the next round's sweep tries again.
- The run report lists each PR once, and a later round that labels the PR, or finds it has carried the label, takes it back out, as does a sweep that no longer finds it open. The run ends red only for the open PRs still unlabelled at the end.
- The sweep remembers, for the rest of the run, each PR it found has carried `review:claude`, so it reads a capped PR's label events once a run rather than every round. A failed read isn't remembered.
- The sweep reads each PR's URL, so the run report links each PR it couldn't label.
- `main.mts` now exits 1 when the run report lists any PR without `review:claude`. It does this after writing the report, the same way it handles an intake stop, so the job ends red.
- At startup, `ensureHostLabels` creates `review:claude` (colour `8957e5`, description "Ask Claude to review this PR") if the repository doesn't have it, along with the `sandcastle:*` labels.
  The label's definition is `REVIEW_LABEL_DEFINITION` in `.sandcastle/lib/config.mts`.
  It stays out of `SANDCASTLE_LABELS`, because that list also decides which labels the queue scope refuses and which ones the sweep restores.
- `CLAUDE.md` and `docs/plans/sandcastle-workflow.md` (the label table, **Labelling the PR**, the follow-up sweep, the email notifications and **Observability**) now describe this behaviour.
  The instruction to label old and stopped-run PRs by hand is gone. You only add the label by hand to the PRs that a red run's report lists.

### Verification

- `.sandcastle/lib/follow-up.test.mts` covers the sweep's labelling. It pins that the sweep:
  - labels a Sandcastle PR that has never carried `review:claude`, whether or not it has any label history;
  - leaves a PR alone when the label was taken off it (matching the name case-insensitively), or when the PR carries it now, without reading the PR's label events;
  - never labels a fork's PR, a collaborator's PR, a PR without the Sandcastle marker, a PR into another base, or a PR not on an issue branch;
  - records a failed label add in the report and moves on to the next PR, still follows up a PR whose label add failed, and never throws;
  - only warns on a failed label-event read, records nothing and doesn't tell the owner to label the PR by hand;
  - lists a PR once across repeated failures, and takes it back out when a later sweep labels it, finds it has carried the label, or no longer finds it open;
  - reads a PR's label events once a run once it has found the label carried, and again the next round after a failed read.
- `.sandcastle/lib/github.test.mts` pins the following:
  - `hasCarriedReviewLabel` across empty, unrelated, unlabelled-only, labelled, removed-again and differently-cased label events;
  - `ensureHostLabels` creates `review:claude` with its colour and description only when it's missing, and reads the repository's labels once;
  - the sweep's query returns each PR's URL.
- `.sandcastle/lib/config.test.mts` pins that `SANDCASTLE_LABELS` doesn't include `review:claude`.
- `.sandcastle/lib/report.test.mts` pins `unlabelledPrExitCode` (0 when the list is empty, 1 otherwise) and `UnlabelledPrReport`'s one entry per PR, `resolve` and `retain`.
- `.sandcastle/main.test.mts` pins that `main.mts` sets the exit code from `unlabelledPrExitCode` after `writeRunReport`, and keeps the intake-stop exit code.
  It also pins that `main.mts` calls `ensureHostLabels()` instead of `ensureLabels()` before startup finishes. `.sandcastle/lib/building.test.mts` follows the rename.
- `pnpm run check:sandcastle` passed with all 1226 tests.
  `scripts/gate.sh` also passed: Markdown lint of the changed files, the Sandcastle check, the Release build and every .NET test project.
