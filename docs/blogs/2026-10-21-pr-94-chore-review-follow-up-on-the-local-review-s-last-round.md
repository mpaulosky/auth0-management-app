# chore(review): Follow up on the local review's last round

- **Release tag:** `v0.0.30`
- **Source PR:** [#94](https://github.com/mpaulosky/auth0-management-app/pull/94)

## PR description

### Why

Issue 81 collected follow-ups from the local review's last round: stale or missing documentation of how review threads are answered, a few gaps in the review ledger and its tests, and the Review notes section of a PR description, which a later edit could replace along with the closing line or the footer.

### What changed

- The ledger pins git's `core.bigFileThreshold` and `GIT_ATTR_NOSYSTEM`, so a branch's review key doesn't depend on one person's git config. It refuses a diff git shows only as "Binary files differ": UTF-16 or UTF-32 text, a binary file turned into text, and a text file with a stray NUL (only a binary format's extension may hold one).
- The `## Review notes` section sits between <code>&#60;&#33;&#45;&#45; review&#45;notes &#45;&#45;&#62;</code> markers, and `scripts/review.sh body` replaces it without touching `Fixes` or the footer. It refuses a body it can't splice safely and tells the skill to ask the person.
- The `pre-push-review` skill's step 9 uses that command. It also says to push a fix before replying to or resolving a thread, since resolving the last thread lets PR Auto-Merge merge without the fix.
- CLAUDE.md and `docs/CONTRIBUTING.md` give one reply, "Left for the owner.", for every thread that isn't fixed, say where a declined thread's reason goes, and name the maintainer's email for a private reason. `docs/SECURITY.md` describes the repo's Claude settings and roots the `.env` deny rules with `//**`.
- Sandcastle's reviewer PR body is refused, and the generic body used, when it holds markup GitHub hides, a character reference, a character outside plain English, or the words Review notes however spelled (`visibleLetters` reads the text several ways). Its mentions and issue references are broken so it closes and notifies no one, and its length is measured after that.
- Tests: the gate's reruns for the reviewer agent, the skill and `settings.json`, the agent front matter, the ledger's old-git guard and binary cases, and every prompt file's shell-expansion hazard.

### Verification

- `scripts/gate.sh` passed without `GATE_SKIP_REVIEW` (all 827 .NET tests and the Sandcastle check's tests), and the pre-push hook passed.
- The local review ran five rounds (four earlier, one of the last fixes). The Critical and Advisory findings it could fix are fixed behind tests. The rest are in the Review notes below, in issue 88, or reported privately.

### Baseline change needed

`docs/PROCESS.md` line 64 still says to resolve each thread "or reply with why not". It is an Owned Baseline file, so it can't change here: the Template needs the repository's rule (fix and push first, then reply, and "Left for the owner." otherwise). Filed in the dotfiles repository as issue 269.
