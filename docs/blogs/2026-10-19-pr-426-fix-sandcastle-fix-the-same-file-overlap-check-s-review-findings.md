# fix(sandcastle): Fix the same-file overlap check's review findings

- **Release tag:** `v0.0.177`
- **Source PR:** [#426](https://github.com/mpaulosky/Blazor-Server/pull/426)

## PR description

Closes #425

### Why

The same-file overlap check from #421 stops Sandcastle from building, in the same run, two issues that change the same file. It merged with six review findings still open.
Because of them it could stall or fail open:

- Two picks that named no files deferred each other, so neither was built.
- A hold behind another pick lasted the whole run, even when that pick was deferred by the critique or opened no pull request.
- Paths were compared as exact strings, so an absolute sandbox path, `./x` or a folder matched nothing.
- A pull request's file list could stop at 100 paths.
- The critique didn't get the `files` its prompt says each pick carries, and it saw an overlap-deferred pick as unpicked work.
- A pick deferred behind an open pull request got a new deferral comment on every run.

The impact falls on the maintainer: issues waited for nothing, builds conflicted when the check failed open, and repeated comments cluttered the issues.

### What changed

- Picks with no `files` no longer block each other.
  Such a pick waits behind the first kept pick or open pull request.
  When there's neither, the first one is built and the rest wait behind it (`lib/overlap.mts`).
- `deferOverlaps` now returns a hold for each deferred pick instead of linking it as blocked by the pick it waits on.
  `main.mts` keeps a hold for the rest of the run only when the pick waits on a pull request, or on a pick that opened one (`lastingHolds`).
  Every other hold is released when the round ends, however it ends.
- `resolveFiles` (`lib/plan.mts`) turns an absolute path under the sandbox checkout into a repo-relative one, and drops `./` and trailing slashes.
  It leaves out blanks, entries with control characters and paths outside the repository.
  `readyPicks` applies it, and the overlap check treats a folder as covering the paths under it.
- `pullRequestFiles` reads <code>GET &#47;pulls&#47;&#123;n&#125;&#47;files</code> with `--paginate`, and counts a renamed file under its old path too.
- The critique gets each pick's `files` (`pickIssues`), and a pick the overlap check deferred isn't passed to it as unpicked (`unpickedReady`).
  `critique-prompt.md` says the files are a prediction.
- The deferral comment carries a marker (`OVERLAP_MARKER`).
  `hostCommentedWith` finds the host's own marked comment, so a pick deferred again in a later run isn't commented on again.
  Every comment check runs before any write.
- A refactor in `lib/overlap.mts` replaces a nested ternary and the `!` lookups with plain if/else and paired lists, with no change in behaviour.
- `docs/plans/sandcastle-workflow.md` describes the new behaviour.

There was no design note for this issue.
`OverlapGitHub.addBlockedBy` and the deferral's `linked` flag stay, though nothing links now, because the existing test stubs still pass them.

### Verification

- `.sandcastle/lib/overlap.test.mts` pins these behaviours:
  - Picks with no files hold behind the first such pick, a kept pick or an open pull request.
  - Each deferral reports what it is held behind.
  - `lastingHolds` keeps a hold behind a pull request or a published pick, and releases the others.
  - A folder covers the paths under it, but not a sibling that only shares its prefix.
  - A pick already commented on is still deferred, but isn't commented on again.
  - A failed comment read throws.
- `.sandcastle/lib/plan.test.mts` pins `resolveFiles` for absolute paths, `./`, trailing slashes, spaces, blanks, control characters, paths outside the root and duplicates.
  It also pins `readyPicks` resolving files, `pickIssues` carrying files and roles, and `unpickedReady` leaving out every planned pick.
- `.sandcastle/lib/github.test.mts` pins `pullRequestFiles` reading the paginated REST endpoint across 250 paths and throwing when `gh` fails.
  It also pins `hostCommentedWith` counting only the host's own marked comment.
- `.sandcastle/lib/prompts.test.mts` pins the critique's picks carrying `files`.
- `.sandcastle/main.test.mts` pins `main.mts` calling `lastingHolds` after the critique and the build, and using `pickIssues` and `unpickedReady`.
- `scripts/gate.sh` passed on the final commit: the Markdown lint, the Sandcastle type-check and tests, the Release build and every .NET test project.
