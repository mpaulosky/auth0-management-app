# docs(sandcastle): Bring the plan's issue table up to date and add a Sandcastle task template

- **Release tag:** `v0.0.98`
- **Source PR:** [#205](https://github.com/mpaulosky/Blazor-Server/pull/205)

## PR description

### Why

An audit of the open `Sandcastle` issues found two gaps outside the issues themselves:

- The "Implementation issues" table in `docs/plans/sandcastle-workflow.md` was out of date. It still listed #80, which
  was closed as not planned and split into #146 and #147. It didn't list #149 or #150, and it didn't show blockers added
  since the plan was written.
- The feature request template has no Summary and no acceptance criteria. An issue filed from it would fail the
  Definition of Ready, which intake (#74) will enforce.

### What changed

- **Plan table:**
  - #80's row is replaced by #146 (blocked by #74 and #77) and #147 (blocked by #146).
  - New rows for #149 (no blockers) and #150 (blocked by #73).
  - #72 and #73 also list #149, a blocker the critique added because all three change `buildIssue`'s failure and
    publish paths.
  - #81 also lists #77 and #78, whose outcomes its run report covers.
  - #82 lists #146 and #147 in place of #80, and also #150 (now a native link on #82 too), so the trigger waits until
    builds mark the issue they're working on.
  - A short note above the table explains the split and the late additions. The table now matches the issues' native
    "blocked by" links, apart from #150, whose blocker is a `Blocked by #73` line in its body.
- **New `.github/ISSUE_TEMPLATE/sandcastle_task.md`:** a "Sandcastle task" template with Summary, a `Blocked by` line,
  Scope and Acceptance criteria. That's the shape the open Sandcastle issues already use, and it passes the Definition
  of Ready. Its comment says the `Blocked by` line holds an issue back just as a native link does. It doesn't add the
  `Sandcastle` label: Sandcastle builds an issue only once the owner labels it. The issue
  templates are Seed files in the repo-ci-baseline Template, so an Apply won't overwrite this one.

### Verification

- `markdownlint-cli2` passes on both files, and the pre-push gate passed.
- Every row's blockers were checked against <code>gh api repos&#47;mpaulosky&#47;Blazor&#45;Server&#47;issues&#47;&#60;n&#62;&#47;dependencies&#47;blocked&#95;by</code>.
- The template's placeholder `Blocked by #N` line has no issue number, so the blocker check ignores it if it's left in.
