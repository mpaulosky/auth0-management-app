# fix(sandcastle): Accept Sandcastle 0.14's prompt check in prompts test

- **Release tag:** `v0.0.36`
- **Source PR:** [#125](https://github.com/mpaulosky/auth0-management-app/pull/125)

## PR description

### Why

The gate on `main` fails in `.sandcastle/lib/prompts.test.mts`. The test checks that Sandcastle's `promptArgs` check refuses only `null` and
`undefined`, so `UI_ROLE` and `REPO_SKILLS` are safe to pass empty. It found the check with a regex written for 0.12:
<code>const value &#61; sanitizedArgs&#91;key&#93;&#59; if &#40;value &#61;&#61; null&#41; &#123;</code>. The lockfile is on 0.14.0, which writes the same check as
<code>const value &#61; args&#91;key&#93;&#59; if &#40;value &#61;&#61;&#61; null &#124;&#124; value &#61;&#61;&#61; void 0&#41; &#123;</code>. The check still refuses only null and undefined, but the test
didn't recognise it. This failure also blocks the central pins cleanup PR.

### What changed

`.sandcastle/lib/prompts.test.mts` is now the same text as the repo-ci-baseline Template's fixed copy (mpaulosky/Application_Factory#113):

- The regex accepts both releases' shapes.
- The installed package must contain exactly one match.
- A new test runs the regex over both releases' text, two lookalikes, and four checks it must refuse, including one that also refuses `""`.

The file is Owned by the Template, so the next Apply leaves it as it is.
