# fix(sandcastle): Diff the reviewer's branch against origin/main

- **Release tag:** `v0.0.86`
- **Source PR:** [#182](https://github.com/mpaulosky/Blazor-Server/pull/182)

## PR description

### Why

Sandcastle's reviewer always saw an empty diff. `.sandcastle/review-prompt.md` ran <code>git diff &#123;&#123;TARGET&#95;BRANCH&#125;&#125;&#46;&#46;&#46;&#123;&#123;BRANCH&#125;&#125;</code> and <code>git log &#123;&#123;TARGET&#95;BRANCH&#125;&#125;&#46;&#46;&#123;&#123;BRANCH&#125;&#125;</code>, but `TARGET_BRANCH` is a Sandcastle built-in. Inside a `createSandbox()` sandbox, `@ai-hero/sandcastle` 0.12.0 sets it to the sandbox's own branch (`TARGET_BRANCH: worktreeInfo.branch`), and it refuses a `promptArgs` override. So both commands compared the issue branch with itself.

### What changed

- `config.mts` gains `BASE_BRANCH = "origin/main"`. Every issue PR targets `main`, and `fetchMain()` refreshes `origin/main` before each round. The sandbox mounts the host's `.git`, so the ref resolves inside it.
- `issuePromptArgs` passes `BASE_BRANCH`, and the review prompt diffs and logs against <code>&#123;&#123;BASE&#95;BRANCH&#125;&#125;</code>. No other prompt used `TARGET_BRANCH`.
- Tests: `issuePromptArgs` gives `BASE_BRANCH` = `origin/main`, the review prompt diffs against <code>&#123;&#123;BASE&#95;BRANCH&#125;&#125;</code>, and no `.sandcastle` prompt mentions `TARGET_BRANCH`.

This follows the same fix in mpaulosky/Articles#308.

### Verification

- `pnpm run check:sandcastle`: type-check plus 135 tests, all passing. The pre-push gate passed.
- In a scratch clone, on a worktree branch with one commit on top of `origin/main`, the old commands (branch against itself) printed nothing. <code>git diff origin&#47;main&#46;&#46;&#46;&#60;branch&#62;</code> showed the changed file, and <code>git log origin&#47;main&#46;&#46;&#60;branch&#62;</code> showed the commit.
