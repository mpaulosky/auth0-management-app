# fix(sandcastle): Give the sandbox the host's git identity before the follow-up pass merges main

- **Release tag:** `v0.0.175`
- **Source PR:** [#420](https://github.com/mpaulosky/Blazor-Server/pull/420)

## PR description

Closes #419

### Why

When a PR's branch is behind main, Sandcastle's follow-up pass merges main into the branch inside the sandbox before any agent role has run.
`@ai-hero/sandcastle` copies the host's git `user.name` and `user.email` into the sandbox only when a role starts, not when the sandbox is created.
So that early merge had no committer identity, and git refused it with "Committer identity unknown".
The pass then stopped with "merging main into the branch failed" and handed the PR back with `sandcastle:needs-human`, even though the merge itself was clean.
This affected any repository that runs this `.sandcastle/` pipeline, including the ones that ported it, such as dotfiles.

### What changed

- `createCheckedSandbox` in `.sandcastle/lib/build.mts` now sets the host's identity in each sandbox it creates, before handing it over.
  It runs `git config --global user.name` and `user.email` in the sandbox, the same way the library does when a role starts.
  Builds and follow-up passes both get their sandbox from this function.
- The host's values are read with `git config user.name` and `user.email` in the main checkout, through the host-safe `git()` helper.
  A value the host doesn't have, or has set to an empty string, is skipped. When the host has neither, nothing runs in the sandbox.
- Each value is passed to the sandbox's shell as one single-quoted word, so a name with a quote or a space stays intact.
- If a `git config` command fails in the sandbox, the sandbox is closed and the error is thrown.
  The pipeline never gets a sandbox whose merge would fail later.
- `createCheckedSandbox` takes a small `CheckedSandboxHost` (create the sandbox, read the host's identity) so tests can stub both.
  The live wiring is the default.

This changes how the host sets up the sandbox, and the unit tests stub Docker.
It needs a run against a real sandbox before merging.

### Verification

- `.sandcastle/lib/build.test.mts`, `createCheckedSandbox`:
  - sets both `user.name` and `user.email` with `git config --global`;
  - quotes a name that contains a single quote as one shell word;
  - sets the identity before the first `git merge`, so a sandbox that refuses a merge without an identity accepts it;
  - runs nothing in the sandbox when the host has neither value;
  - closes the sandbox and throws, naming the key and git's error, when `git config` fails in it.
- `.sandcastle/lib/follow-up-pass.test.mts`, `runPass`: the follow-up pass gets its sandbox from `createCheckedSandbox`, merges main cleanly before any role has run, and doesn't hand the PR back.
- `scripts/gate.sh` passed on the final commit: the Sandcastle check (type-check and all 1,096 Sandcastle tests), the Release build and every .NET test project.
