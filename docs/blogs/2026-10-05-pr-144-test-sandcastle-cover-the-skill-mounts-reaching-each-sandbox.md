# test(sandcastle): Cover the skill mounts reaching each sandbox

- **Release tag:** `v0.0.72`
- **Source PR:** [#144](https://github.com/mpaulosky/Blazor-Server/pull/144)

## PR description

### Why

PR #142 mounts the host's `dotnet-*` skills into every Sandcastle sandbox through `agentSandbox()` in
`.sandcastle/lib/skills.mts`. `skillMounts`, which finds the skills, had tests, but `agentSandbox()` didn't. No test
would fail if the mounts stopped reaching `docker()`, or if a missing skill were reported on every sandbox instead of
once. Copilot pointed this out in its last review of #142.

### What changed

- `makeAgentSandbox` builds the sandbox factory from a skills folder, a Docker factory and a logger, so tests can stub
  all three. `agentSandbox` is that factory wired to the real `~/.claude/skills`, `docker()` and `console.log`. Its
  callers in `build.mts`, `plan.mts` and `critique.mts` don't change.
- Three tests in `skills.test.mts`: every sandbox gets the found skills' mounts, missing skills are reported once
  however many sandboxes are created, and nothing is logged when every skill is found.

### Verification

- The new tests failed first, because `makeAgentSandbox` didn't exist, then passed with the change.
- `scripts/gate.sh` passed in the pre-push hook: the Sandcastle check (108 tests passed), the Release build and both
  .NET test projects.
