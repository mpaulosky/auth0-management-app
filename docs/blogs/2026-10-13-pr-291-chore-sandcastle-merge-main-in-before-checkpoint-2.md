# chore(sandcastle): Merge main in before checkpoint 2

- **Release tag:** `v0.0.133`
- **Source PR:** [#291](https://github.com/mpaulosky/Blazor-Server/pull/291)

## PR description

### Why

Sandcastle pushes with git hooks off, so the pre-push hook's check that refuses a branch behind `origin/main` never runs on its branches. A build starts from main as it was when the round began and can take an hour, so its PR could open already behind main. Every push should be synced with main first, Sandcastle's included.

### What changed

- `buildIssue` (`.sandcastle/lib/build.mts`): just before checkpoint 2, the host fetches `origin/main` again through a new `BuildHost.latestMain()` (`fetchMain`). When the branch doesn't contain it, the host merges it in inside the sandbox, so checkpoint 2 gates the merged branch.
  - A merge that conflicts is aborted, and the branch is published as it is. The follow-up pass already merges main into a conflicted PR and runs a role to resolve the conflict.
  - A failed fetch publishes without the merge too, and the follow-up pass updates a PR that's behind main.
- Tests: five new `buildIssue` tests, covering:
  - the merge between the reviewer and checkpoint 2
  - pushing the commit checkpoint 2 passed on after the merge
  - no merge when main is already in
  - a conflicting merge that is aborted and still published
  - a failed fetch
- Docs: the pipeline diagram and a "Merging main before checkpoint 2" paragraph in `docs/plans/sandcastle-workflow.md`, plus the matching comments in `.sandcastle/main.mts` and `build.mts`.

This doesn't prevent a conflict between two PRs built in parallel from the same main (like #287 and #288), which only appears once the first one merges. The follow-up pass still handles that case.

`docs/PROCESS.md` is unchanged: it comes from the shared Baseline, and its existing behind-main rule already covers pushes that go through the hook.

### Verification

- `pnpm run check:sandcastle`: 1036 tests pass. The new tests failed before the change.
- The pre-push gate passed. It first refused the push because the branch was one commit behind main, and passed once main was merged in.
