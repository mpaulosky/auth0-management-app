## build: switch the repo tooling from npm to pnpm

- **Release tag:** `v0.0.57`
- **Source PR:** [#113](https://github.com/mpaulosky/Blazor-Server/pull/113)

### PR description

<!-- ccr-projects-attribution: {"github_login":"mpaulosky"} -->
_Requested by **Matthew** · [project thread](https://claude.ai/code/project/chan_01M4TRjuaTvMLM1jqeNd9KNs?thread=cmsg_01M4TRjuaTvMLM1jqeNd9KNsBqvSH7Zyjxovd4Kr4rap1i)_

Before: the root dev tooling (Sandcastle, markdownlint, tsx, TypeScript) installed with npm, the gate ran `npx --no-install markdownlint-cli2` and `npm run check:sandcastle`, and the Sandcastle sandbox ran `npm install`.

After: the repo uses pnpm 12.6.0, pinned through `packageManager`, with a committed `pnpm-lock.yaml`, and `npm install` is refused (`engines.npm` + `engine-strict`), matching atelier-store. The gate, its tests, the sandbox and the docs all use pnpm.

The lockfile was converted with `pnpm import`; I compared both lockfiles and all 148 resolved package versions are identical (pnpm adds only its own package-manager entries).

How:
- `package.json`: `packageManager` and the npm engine block. New `.npmrc`, and `pnpm-workspace.yaml` with `allowBuilds: esbuild: false` (its install script only checks the native binary, which pnpm already installs).
- `scripts/gate.sh`: `pnpm exec markdownlint-cli2`, `pnpm run check:sandcastle`, and the Sandcastle check now triggers on `package.json` or `pnpm-*.yaml` instead of `package*.json`.
- `scripts/tests/gate.test.sh` and `.github/hooks/tests/pre-push.test.sh`: stub `pnpm` instead of `npm`/`npx`; the lockfile case now uses `package.json`, plus a new case for `pnpm-lock.yaml`.
- `.sandcastle/Dockerfile`: `corepack enable pnpm`. `.sandcastle/lib/config.mts`: the sandbox runs `pnpm install --frozen-lockfile --config.confirm-modules-purge=false`, so a node_modules copied from the host (with a different pnpm store) is rebuilt without a TTY prompt.
- `release_post.py` also skips `pnpm-lock.yaml` in release diffs (with tests).
- README (and its `docs/` copy), the pre-commit hint, the Sandcastle role rules, `main.mts` usage comment and the Sandcastle plan doc say pnpm.
- Dependabot keeps `package-ecosystem: "npm"`, which covers pnpm lockfiles. CI needed no change: it doesn't install the root packages.

Verified locally from a clean tree after `pnpm install --frozen-lockfile`: `scripts/gate.sh` passed (yamllint, markdownlint, actionlint, zizmor, shellcheck, Sandcastle check 103/103, Release build, both test projects). `gate.test.sh` 19/19, `pre-push.test.sh` 20/20 and the release-post pytest suite 54/54 pass. I also ran the sandbox install in `node:22-bookworm` with corepack, both fresh and over a copied host `node_modules`; both succeed. The same gate passed on `main` beforehand.
