# feat(sandcastle): Follow up on hand-opened PRs labelled for it

- **Release tag:** `v0.0.21`
- **Source PR:** [#70](https://github.com/mpaulosky/auth0-management-app/pull/70)

## PR description

Closes #58

### Why

Sandcastle's follow-up sweep only acted on the PRs Sandcastle opened itself. A PR a person opened got no help with its review threads, red checks or falling behind `main`, and PR Auto-Merge held it on every unresolved thread.
The session watcher from #54 covers a PR only while the session that opened it is still running. Once the laptop closes, the conversation ends, or the PR came from GitHub's web editor, nothing follows the PR up.

This change adds an opt-in label, `sandcastle:follow-up`. The repository owner, or the session handing a PR off, adds it to a hand-opened PR, and Sandcastle then follows that PR up like one of its own.

### What changed

- **The label.** `sandcastle:follow-up` (`FOLLOW_UP_LABEL` in `lib/config.mts`) is created at startup by `ensureHostLabels`, next to `review:claude`.
  It stays out of `SANDCASTLE_LABELS`, because a person applies it and the sweep never puts it back.
- **The sweep accepts a labelled PR** (`sweepSubject` and `sweepSkipReason` in `lib/follow-up.mts`). The PR needs no Sandcastle marker, no issue branch and no in-scope issue.
  It must come from the same repository, target `main`, and use a branch name `scripts/check-branch-name.sh` accepts (<code>feature&#124;fix&#124;hotfix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code> or <code>chore&#47;&#123;slug&#125;</code>, through `isHandOffBranch`).
  A branch name reaches a shell in the sandbox, and this rule also keeps Sandcastle off `dev`, `preview` and `dependabot/*`.
  Only runs in the default `Sandcastle` queue scope follow hand-off PRs, so a local run on one issue or another label never touches them.
- **Only the owner's label counts.** The sweep checks the PR's events and body edits with `approval`, the same rule the `Sandcastle` label uses on an issue.
  If a stranger added the label, or someone else renamed the PR or edited its body after the owner added it, the sweep logs the PR and writes nothing to it.
  If the owner check can't answer, a follow-up run ends red. Approval is checked again after the pass reads the PR's text.
- **The PR is the subject.** A hand-off PR's pass claims `sandcastle:building` on the PR itself, takes its brief from the PR's title, description and the comments of people with write access (`pullRequestText`), and hands back on the PR.
  A Sandcastle PR of an in-scope issue keeps its issue as the subject, label or not. `isSandcastlePullRequest` stays strict, so a closed hand-off PR never triggers an issue hand-back and its branch is never deleted.
- **Labels on PRs.** `sandcastle:building` is now read, added and removed through the REST labels endpoints (`labelsOn`, `addLabelOn`, `removeLabelFrom`, `openNumbersWithLabel` in `lib/github.mts`), which work for issues and PRs.
  This covers builds as well. The startup cleanup of stale claims now finds claims on PRs too. `bodyEdits` can read a PR's edits as well as an issue's.
- **Prompts.** `PassBrief` and `briefPromptArgs` in `lib/prompts.mts` give the follow-up and gate-fixer roles either an issue or a PR's own text.
  Their prompts now have a `# THE BRIEF` section that opens with <code>&#123;&#123;BRIEF&#95;SOURCE&#125;&#125;</code>, so an issue's rendered line reads as it did before.
- **Thread rules on a hand-off PR.** #54's decline rule applies: a pass resolves a thread only when Copilot or Claude Review opened it and the verdict is `fixed` (`ResolveRule`, `isReviewBot`).
  Declined and outdated threads get a reply and stay open for the owner. Sandcastle PRs resolve threads as before.
  A reply posted with the host's login that carries <code>&#60;&#33;&#45;&#45; claude&#45;session &#45;&#45;&#62;</code> counts as the host's own reply, so the first pass after a hand-off doesn't answer again the threads the session already declined.
- **Docs.** `CLAUDE.md` says to add the label when you stop watching a PR, and to stop running `scripts/watch-pr.sh` and stop pushing to the branch once it's on.
  `docs/CONTRIBUTING.md` and `docs/plans/sandcastle-workflow.md` describe hand-off PRs, the label, and claims sitting on PRs.
  The plan now says the owner can set `SANDCASTLE_FOLLOW_UP_LABEL`. The workflow side landed in #60, so this branch changes no workflow file.
- A final refactor commit shares one issue-branch regex between `isIssueBranch` and `isHandOffBranch`, untangles the claim re-read before a sweep write, and rewrites a few comments. It changes no behaviour.

The branch follows the design note. It made no departures.
