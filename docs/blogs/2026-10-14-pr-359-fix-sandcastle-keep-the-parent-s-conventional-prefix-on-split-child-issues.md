# fix(sandcastle): Keep the parent's conventional prefix on split child issues

- **Release tag:** `v0.0.154`
- **Source PR:** [#359](https://github.com/mpaulosky/Blazor-Server/pull/359)

## PR description

Closes #351

### Why

When Sandcastle's intake splits a large issue into child issues, it posts the child titles exactly as the model wrote them.
The model left out the parent's conventional-commit prefix (such as `feat(ui):`), so the pull requests built from those children failed the **PR title** check.
That check matters because a PR's title becomes the squash commit's subject on `main` and the Release's name.
This happened when #347 was split into #348 and #349: the PR built from #348 failed until someone fixed both titles by hand.

### What changed

- `applySplit` in `.sandcastle/lib/intake.mts` now runs each child title through a new `withParentPrefix` helper before posting it.
  If the parent title starts with a conventional prefix and the child's drafted title doesn't, the helper puts the parent's prefix in front, exactly as written (`type(scope): `, `type: `, with or without `!`).
  A drafted title that already has its own prefix, or a parent title with no prefix, is left as drafted.
- The prefix pattern accepts the same type list as `scripts/check-pr-title.sh`, so a child counts as already prefixed only when its PR title would pass the check.
  For example, a drafted `Note: X` still gets the parent's prefix.
- The prefix is added before `withoutReferences`, so mentions and cross-references in the posted title are still broken.
  The umbrella comment lists the children by the titles that were actually posted.
- In `.sandcastle/intake-prompt.md`, the Splitting section now asks for the original issue's prefix on each child title, and the split example's child titles start with `feat(ui):`, so the prompt matches what the host posts.

### Verification

- `.sandcastle/lib/intake.test.mts` has a new block, "applyVerdicts for a split verdict's child titles", with six tests:
  - a `feat(ui):` parent gives its prefix to bare child titles;
  - a child drafted as `fix(ui): …` is posted unchanged;
  - a `feat(ui)!:` parent and a scopeless `chore:` parent each pass their prefix on as written;
  - a parent without a prefix leaves the child titles as drafted;
  - the umbrella comment names each child by its posted, prefixed title.
- The tests were committed red first, and four of them failed against the old code. The fix commit left them unchanged.
- `pnpm run check:sandcastle` passed: 1,088 tests, no failures.
- `scripts/gate.sh` passed: Markdown lint, the Sandcastle TypeScript check, the Release build and every .NET test project.
