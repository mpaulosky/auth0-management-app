# fix(sandcastle): Mount the .git config and hooks through the provider's create()

- **Release tag:** `v0.0.92`
- **Source PR:** [#195](https://github.com/mpaulosky/Blazor-Server/pull/195)

## PR description

### Why

Since #188, every Sandcastle run has stopped at its first sandbox, before any role runs. #188 mounts `.git/config`
read-only through <code>docker&#40;&#123; mounts &#125;&#41;</code>, and Sandcastle 0.12's `docker()` refuses any file mount whose parent directory
is outside `/home/agent`. The unit tests replace `docker()` with a stub, so they didn't catch it.

### What changed

- `makeAgentSandbox` (`.sandcastle/lib/skills.mts`) passes only the skill mounts to `docker()`. The new
  `withCreateMounts` wraps the provider's `create()` and adds the read-only `.git/config` and `.git/hooks` mounts to the
  ones Sandcastle creates each sandbox with (the worktree and the shared `.git` directory). Sandcastle doesn't check
  those mounts.
- `SandboxProvider`'s public type doesn't declare `create()`, so `withCreateMounts` checks for a bind-mount `create()`
  at run time. If a future Sandcastle version doesn't have one, it throws instead of running sandboxes without the
  protection.
- The tests now cover three things: a stub `create()` receives Sandcastle's mounts plus the `.git` ones, the wrapped
  provider keeps its other members, and a provider without a
  bind-mount `create()` is refused.

### Verification

- `scripts/gate.sh` passes, including `pnpm run check:sandcastle` (191 tests).
- Smoke test with the real `docker()` provider, the main checkout's `.git` and the Sandcastle image: inside the sandbox,
  appending to `.git/config`, renaming a file over it and adding a file to `.git/hooks` were all refused. Writing
  elsewhere in `.git` and reading the config with `git config` still worked. The host's `.git/config` hash was unchanged
  afterwards.
