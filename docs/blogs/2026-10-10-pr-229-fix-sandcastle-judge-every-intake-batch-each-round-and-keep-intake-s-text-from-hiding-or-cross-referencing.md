# fix(sandcastle): Judge every intake batch each round, and keep intake's text from hiding or cross-referencing

- **Release tag:** `v0.0.109`
- **Source PR:** [#229](https://github.com/mpaulosky/Blazor-Server/pull/229)

## PR description

Closes #227

### Why

Claude reviewed #225's final push, but its findings were posted only after the PR had merged. All three are real
(#227):

- **A stuck first batch starved the backlog.** `intakeRound` sent only the first `INTAKE_BATCH_SIZE` unjudged issues.
  If that batch never yields verdicts (a malformed or truncated answer every time), every later round and run re-sent
  it, and issue 11 onward was never judged, while the log said they would be.
- **Raw HTML got through `plainText`.** An unclosed <code>&#60;details&#62;</code> in intake's reason could fold the questions and the
  re-queue instructions into a collapsed toggle, and a <code>&#60;&#33;&#45;&#45;</code> hides what follows it.
- **Some cross-references got through.** `GH-123` autolinks, and a <code>github&#46;com&#47;&#60;owner&#62;&#47;&#60;repo&#62;&#47;issues&#47;N</code> or `/pull/N`
  URL puts a "mentioned this" event on the target, in any repo.

### What changed

- `intakeRound` (`.sandcastle/lib/intake.mts`) now runs intake once per batch of `INTAKE_BATCH_SIZE` over the whole
  backlog each round, and the next batch still runs after one fails.
  - A failed batch would re-form with the same issues every round, so it's tried again in halves, and every failing
    half again. Each issue that breaks intake's answer is left unjudged on its own, and the rest are judged.
  - Whatever is left is logged and judged again in a later round or run.
  - Intake stops for the round after `INTAKE_FAILED_RUNS_LIMIT` (8, in `config.mts`) failed runs in a row, so a failure
    every run hits costs 8 runs, not one per split of every batch. 8 leaves room to narrow down three bad issues next to
    each other in a full batch.
  - Intake also stops once GitHub has refused every verdict in `INTAKE_REFUSED_BATCHES_LIMIT` (2) batches in a row.
    A batch counts only when GitHub refused more than one verdict in it and applied none: a single refused edit can
    be the issue's own, and narrowing makes single-issue batches back to back. Any other run that answered resets the
    count. `applyVerdicts` now returns how many verdicts it applied and how many
    failed.
  - Narrowing checks for a stop before it logs, so the log never announces a split that won't happen.
  - An `UncountedStopError` (a usage limit or time budget) still ends the run.
  - A new `warn` parameter takes the failure lines, as `intakePhase`'s does.
- `plainText` now also escapes `&` as `&amp;` and <code>&#60;</code> as `&lt;`, and adds a zero-width space after `GH-` before digits
  and before the dot of `github.com`. Escaping `&` stops a character reference such as `&#64;` or `&#35;` from
  decoding into an `@` or `#` that the other rules never saw.
- The comments on `plainText`, `intakeRound` and `INTAKE_BATCH_SIZE` (`config.mts`) say what the code now does.

### Verification

- New tests, written first and seen failing:
  - Every batch is sent in the same round.
  - The issue that breaks its batch is logged, and the next batch is still judged.
  - In a batch where one issue always breaks the run, the other nine are judged.
  - With two bad issues, one in each half, the other eight are judged.
  - When every run fails, exactly `INTAKE_FAILED_RUNS_LIMIT` runs happen.
  - When gh fails every call, two runs happen and intake stops for the round.
  - When GitHub refuses the only verdict in one batch, the next batch is still judged.
  - Single-issue batches from narrowing that GitHub refuses one after another don't stop intake, and a good batch
    between two refused ones resets the count.
  - Once intake stops, the log doesn't announce a split it never tries.
  - The `hostile` comment string now includes <code>&#60;details&#62;</code>, <code>&#60;&#33;&#45;&#45;</code>, `GH-67`, a `github.com` issue URL and character
    references (`&#64;`, `&commat;`, `&#35;`, `&#46;`). The test asserts that every `&` in the output is escaped.
- A new test checks that an `UncountedStopError` from a batch ends the round without judging the next batch.
- Mutation checks: each test goes red when I remove the code it covers. That covers the stop rethrow, splitting and recursing into every failed half, both stops, both counts' resets, the stop check before a split is logged, the `&` and <code>&#60;</code> escapes,
  the `GH-` break, the `github.com` break, and limiting the loop to one batch.
- `pnpm run check:sandcastle` passes, and so does `scripts/gate.sh` on push.
