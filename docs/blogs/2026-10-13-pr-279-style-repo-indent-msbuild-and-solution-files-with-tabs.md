# style(repo): Indent MSBuild and solution files with tabs

- **Release tag:** `v0.0.127`
- **Source PR:** [#279](https://github.com/mpaulosky/Blazor-Server/pull/279)

## PR description

### Why

`CODING_STANDARDS.md` says `.csproj` files are indented with tabs, but `.editorconfig` set no indent style for `.csproj`, `.props`, `.targets` or `.slnx` files. IDEs fell back to their own default, and a Rider reformat re-indented every project file with spaces. While doing that it also removed the leading space from <code>&#60;TailwindMinify&#62; &#45;&#45;minify&#60;&#47;TailwindMinify&#62;</code>, which would have run the Release CSS build with `app.css--minify`. That edit isn't in this PR; the space is kept.

### What changed

- `.editorconfig`: the tab-indented section now covers `csproj`, `props`, `targets` and `slnx`. The modifier-order list is unspaced again, and the file ends with a newline.
- Project, props and solution files: indented with tabs, as `.editorconfig` now requires.
- Three C# continuation lines no longer mix tabs with space alignment (`CentralPackageManagementTests`, `ServiceDefaultsExtensions`, `ProjectReferenceRule`).
- The same IDE pass rewrapped some long C#, Razor and Markdown lines. Those changes are formatting only.

No behaviour changes. Package versions and project settings are unchanged.

### Verification

- The pre-push `scripts/gate.sh` passed: lints, Release build and every test project.
- `git diff -w` on the MSBuild files shows no changes beyond whitespace.
