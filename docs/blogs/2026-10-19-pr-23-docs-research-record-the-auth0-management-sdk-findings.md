# docs(research): Record the Auth0 Management SDK findings

- **Release tag:** `v0.0.7`
- **Source PR:** [#23](https://github.com/mpaulosky/auth0-management-app/pull/23)

## PR description

### Why

The map [Manage Users and Roles](https://github.com/mpaulosky/auth0-management-app/issues/11) asked which version of the `Auth0.ManagementApi` SDK the feature should use, and which calls it needs ([#12](https://github.com/mpaulosky/auth0-management-app/issues/12)). This PR records the answer in the repo, so the spec and the Sandcastle issues can link to it.

### What changed

- `docs/research/auth0-management-sdk.md` records the findings, each with its source:
  - Pin `Auth0.ManagementApi` 10.5.0. A scratch `net10.0` project built it with no warnings and no audit findings.
  - Build one `ManagementClient` from a singleton `ClientCredentialsTokenProvider`, which caches the token.
  - The SDK throws a `ManagementApiException` on every non-2xx response. Each call maps its own status codes to stable `Result` error codes, because a 404 or a 409 means different things on different calls. A 503 from a too-heavy User search becomes `User.SearchTooBroad`, not an exception.
  - <code>PATCH &#47;users&#47;&#123;id&#125;</code> refuses some Profile Fields depending on the User's connection, and each refusal comes back as a 400.
  - The six permissions listed in `CLAUDE.md` are probably one short: Auth0's reference lists `read:role_members` for listing a User's Roles and a Role's Users.
