# feat(UI): Add the Alert and the Management API error boundary

- **Release tag:** `v0.0.11`
- **Source PR:** [#44](https://github.com/mpaulosky/auth0-management-app/pull/44)

## PR description

Closes #33

### Why

The User and Role management pages need one consistent way to show a failure to an Admin.
A failed `Result` from the Management API, such as a rate limit, needs a visible message beside the action that failed.
A Management API the app can't reach at all needs a message in place of the page's content and a way to try again, instead of the app's generic error page.
This change adds the two shared components the management pages will use for this. No page uses them yet: each slice's own issue wraps its content in them.

### What changed

- `src/UI/Components/Shared/Alert.razor` and the `AlertTone` enum (`Error`, `Warning`).
  `Alert` renders its `ChildContent` with `role="alert"`, in the fixed red hue for Error and the fixed amber hue for Warning, with `dark:` variants for both Themes.
  It uses no `accent-*` colour, because these colours keep their meaning whatever the Palette.
  It follows the same tone switch as `Badge`, and like the other shared components it takes `Class` and passes other attributes through.
- `src/UI/Components/Shared/ManagementApiErrorBoundary.razor` wraps its `ChildContent` in an <code>&#60;ErrorBoundary&#62;</code>.
  When a child throws, it shows an Error `Alert` that says "The app couldn't reach Auth0's Management API. Try again, or ask whoever runs the app to check its Auth0 Management settings."
  - When `RendererInfo.IsInteractive` is true, **Try again** is a button that calls the boundary's `Recover()`, so the child renders again.
  - When the page renders statically, an `@onclick` never runs, so **Try again** is a link to the current URL that reloads the page.
- Neither component depends on a feature slice.
- There was no design note for this issue, so nothing departs from one.
  The review on this PR asked for three changes, all made: read `RendererInfo` directly instead of catching `Exception` to suit bUnit, test a child that throws after an `await`, and give `Alert` `Class` and attribute pass-through.

### Verification

- `tests/UI.Tests.Unit/Components/Shared/AlertTests.cs` checks that both tones render with `role="alert"` and show their child content.
  It also checks that each tone uses its own hue with a `dark:` text variant and none of the other tone's hue, that neither tone uses an `accent-*` class, and that `Class` and extra attributes reach the alert.
- `tests/UI.Tests.Unit/Components/Shared/ManagementApiErrorBoundaryTests.cs` checks that:
  - a child that doesn't throw renders without the message, and a child that throws, while rendering or after an `await` in `OnInitializedAsync`, is replaced by the exact message;
  - in interactive rendering, **Try again** is a button, and clicking it renders the child again once it stops throwing;
  - in static rendering, **Try again** is a link to the current URL, and there's no button.
- The existing `UiAssembly_SharedComponents_DependOnNoFeatureSlice` architecture test covers the new components and passes.
- `scripts/gate.sh` passed on the final branch.
  It ran the lint step (no changed Markdown, YAML, workflow or shell files), the Release build, and every test project:
  Architecture.Tests, Domain.Tests.Unit, UI.Tests.Unit, UI.Tests.Integration, AppHost.Tests.Integration and UI.Tests.E2E.
  One E2E test that needs a real Auth0 tenant was skipped.
