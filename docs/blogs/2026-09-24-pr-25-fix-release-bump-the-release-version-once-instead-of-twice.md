## fix(release): Bump the release version once instead of twice

- **Release tag:** `v0.0.31`
- **Source PR:** [#25](https://github.com/mpaulosky/Blazor-Server/pull/25)

### PR description

## Summary

Releases skipped numbers (v0.0.19, 21, 23 … 27, 30) because the version was bumped twice: GitVersion already returned the *next* version (one patch per commit on `main` since the last tag, including `[skip-release]` docs merges), and "Compute next version" then added another bump.

## Changes

- **Bump once.** "Compute next version" now bases the version on the highest `vX.Y.Z` tag (`git tag --list 'v[0-9]*' --sort=-v:refname`, falling back to `v0.0.0`) and applies only the label-driven bump. It deliberately avoids `git describe`, which returns the nearest ancestor tag rather than the highest version.
- **Remove GitVersion.** Dropped "Setup .NET", "Install GitVersion", "Get version base from GitVersion" and the `GV_*` env vars, and deleted `GitVersion.yml` (nothing else referenced it). The `+semver:` commit-message bumps it configured go away on purpose; PR labels are the only bump mechanism now.
- **Fix multi-label bump detection.** `jq -e '.[] | test(...)'` sets its exit status from the *last* label only, so a PR labelled `semver:minor` + `bug` released as a patch. Switched to `any(.[]; test(...))`.
- Unchanged: bump precedence (major > minor > patch, default patch), the "tag already exists → increment patch" loop, the `[skip-release]` gate, and all existing tags/releases.
