# refactor(ui): Move LocalReturnUrl to a cross-cutting UI.Security

- **Release tag:** `v0.0.157`
- **Source PR:** [#370](https://github.com/mpaulosky/Blazor-Server/pull/370)

## PR description

Closes #362

### Why

`LocalReturnUrl` is the rule that keeps a visitor-supplied `returnUrl` pointing inside the app, so an endpoint can't be used to redirect somewhere else.
It lived in the Authentication slice, because only the login endpoint needed it.
The coming Theme and Palette endpoints need the same rule, and slices can't use each other's types.
This change moves the rule into a cross-cutting `UI.Security` namespace that any slice can use, as the Theme and Palette spec and ADR 0007 describe.
Nothing changes for visitors: the login endpoint validates its return URL exactly as before.

### What changed

- `LocalReturnUrl` moves from `src/UI/Components/Features/Authentication/` to `src/UI/Security/LocalReturnUrl.cs`, in namespace `UI.Security`.
  Its code is unchanged. Its summary comment now says "an endpoint" rather than "the login endpoint", because more than one endpoint will use it.
- `AuthenticationEndpoints` imports `UI.Security`. The login endpoint still passes `returnUrl` through `LocalReturnUrl.OrRoot`.
- `LocalReturnUrlTests` moves to `tests/UI.Tests.Unit/Security/`, in namespace `UI.Tests.Unit.Security`. Only its `using` and namespace lines changed.
- A new architecture test, `UiAssembly_Security_DependsOnNoFeatureSlice` in `tests/Architecture.Tests/UiTests.cs`, reuses `SharedDependencyRule`.
  It fails if any type in `UI.Security` depends on a `UI.Components.Features` namespace.
  It also fails if `UI.Security` holds no types, so a typo in the namespace can't let the rule pass without checking anything.
- The **Project layout** section of `CLAUDE.md` now names `src/UI/Security/`: cross-cutting code that isn't a component and depends on no slice, as ADR 0007 describes.

### Verification

- `tests/UI.Tests.Unit/Security/LocalReturnUrlTests.cs`: the moved tests pass. They differ from the originals only in their namespaces, so they check that the rule behaves as before.
- `tests/Architecture.Tests/UiTests.cs`: `UiAssembly_Security_DependsOnNoFeatureSlice` checks that `UI.Security` depends on no feature slice and isn't empty. It passes.
- `tests/UI.Tests.Integration/Components/Features/Authentication/LoginEndpointTests.cs` passes unchanged, so the login endpoint still validates its return URL.
- `scripts/gate.sh` passed on the final commit.
  That run covered the Markdown lint, the Release build and every test project: Architecture, Domain unit, UI unit, UI integration, AppHost integration and UI E2E.
  The E2E test that needs a reachable Auth0 tenant was skipped, as it always is.
