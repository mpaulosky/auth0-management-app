# feat: Warn when the git hooks aren't enabled, so the pre-push gate isn't silently skipped

- **Release tag:** `v0.0.25`
- **Source PR:** [#75](https://github.com/mpaulosky/auth0-management-app/pull/75)

## PR description

Closes #62

### Why

The pre-push gate only runs in a clone where `git config core.hooksPath` is set to `.github/hooks`.
Without that setting, git never runs `.github/hooks/pre-push`, and a push skips the gate without saying so.
That is how a Markdown line over the 200-character limit reached PR #60 and failed the required markdownlint check in CI.
It is also why the pushes for PRs #54 and #60 were wrongly described as having passed the gate.
The setup step is documented, but nothing tells you when it was missed.
This affects anyone who pushes from a clone, and mostly Claude Code sessions, since most pushes come from them.

### What changed

- `scripts/check-git-hooks.sh` is a new script that checks `core.hooksPath` in the repository the session starts in.
  When the setting isn't `.github/hooks`, it prints a JSON warning for Claude Code.
  The warning says the pre-push gate won't run, and names the fix, `git config core.hooksPath .github/hooks`.
  `systemMessage` shows the warning to the person, and `additionalContext` passes it to the agent.
  When the setting is correct, the script prints nothing.
  Outside a git repository, or when `git` is missing, it prints nothing and always exits 0, so it never stops a session.
- `.claude/settings.json` is a new file that registers the script as a Claude Code `SessionStart` hook.
- `.github/ci/gate-checks.sh` runs the script's test when the script or the test changes.
  `ci.yml`'s "Hook tests" job is Owned by the CI Baseline, so the test is wired into the gate rather than into that job.
- `CLAUDE.md` (Commands) says the hooks run only when `core.hooksPath` is set, and points to the new session warning.
  It also says not to report the pre-push gate as passed unless the hook's "All gates passed" line was seen, or `scripts/gate.sh` was run by hand and passed.
  The list of checks in `gate-checks.sh` now includes this test.

The issue's other two options, a `prepare` script in `package.json` and a warning from the UI build, weren't built, as the issue decided.

### Verification

- `scripts/tests/check-git-hooks.test.sh` runs the script in throwaway repositories, with git's global and system config kept out of the way. It checks:
  - With `core.hooksPath` unset, empty, `.githooks` or `.git/hooks`, the script exits 0 with a warning that mentions the pre-push gate, says it won't run, and names the fix.
    That holds from the repository root and from a subdirectory.
    The warning parses as JSON and carries both `systemMessage` and `hookSpecificOutput.additionalContext`.
  - With `.github/hooks` set, the script prints nothing, from the root and from a subdirectory.
  - Outside a git repository, and with no `git` on `PATH`, it exits 0 and prints nothing.
  - `.claude/settings.json` registers a `SessionStart` command that runs `scripts/check-git-hooks.sh`, and the script is executable.
  - `.github/ci/gate-checks.sh` runs the test when either file changes.
  - The `CLAUDE.md` Commands section has the rule about reporting the gate as passed.
- `scripts/gate.sh` passed on the final branch: Markdown and shell lint of the changed files, the repo checks (including this test, 13 passed), the Release build and every test project.
- The tests can't check that Claude Code really shows the hook's output when a session starts, since that is the host's behaviour.
