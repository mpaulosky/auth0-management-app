# feat(review): Review every branch locally before it's pushed

- **Release tag:** `v0.0.27`
- **Source PR:** [#82](https://github.com/mpaulosky/auth0-management-app/pull/82)

## PR description

### Why

Most of the review threads GitHub's reviewers opened on this repo's PRs were about behaviour a review before the push could have caught: 166 threads in three days, 160 of them from Claude Review. Hand-opened PRs got no local review at all, and Sandcastle's local reviewer asked far less than Claude Review does. This moves the heaviest review onto the developer's machine, before the push, so GitHub's reviewers stay as a backstop that finds little.

### What changed

- **`/pre-push-review` skill** (`.claude/skills/pre-push-review/`): reviews the branch's whole diff against `origin/main` with parallel reviewers. One reviewer applies the bar from Claude Review's own prompt (`review-bar.md`), and one more applies each matching lens from the code-review skill. The skill fixes each finding behind a regression test, reviews again, and records the outcome. Reviewers run as a new read-only agent, `.claude/agents/pre-push-reviewer.md` (Read, Grep and Glob only), because they read text people without write access wrote.
- **Review ledger** (`.sandcastle/lib/review-ledger.mts`, run as `scripts/review.sh`): keeps each review under `.git/review/`, keyed by the branch's own hunks. A clean merge of `main` keeps the review, and a new commit needs a new one. Only the person accepts a finding (`scripts/review.sh accept`), and an acceptance never carries to a later review. Finding ids are unique along a branch, so an accept can't land on the wrong finding. Ledgers are owner-only, and `.claude/settings.json` denies Claude Code reading them directly.
- **Gate:** `.github/ci/gate-checks.sh` runs `scripts/review.sh check` first and refuses a diff without a clean recorded review. `GATE_SKIP_REVIEW=1` skips it for gate runs while iterating, never for a push.
- **Sandcastle:** its sandboxes skip the check (`SANDBOX_ENV` in `lib/skills.mts`) until its reviewer runs the same review. Every sandbox gets an empty read-only folder over `.git/review`, at every path a mount puts `.git`, alongside the existing read-only `.git/config` and `.git/hooks`. Those covers now also reach the head-mode roles (planner, critique, intake).
- **Docs:** CLAUDE.md, README, CONTRIBUTING (Claude Code and git 2.38+ are now required), SECURITY.md and the Sandcastle plan describe the review. Accepted security findings are only counted in public notes and are reported privately. On every review thread a session leaves unresolved without a fix, the session replies only "Left for the owner.".

### Baseline change needed

`.github/workflows/claude-review.yml` (Owned), made in the repo-ci-baseline Template and re-Applied. The local review now does the heavy pass over the whole branch before every push. Claude Review should check for what the local review missed, not repeat the whole review. On this PR, a 13-line push brought a full re-review of about 3,000 lines and 3 new threads on code the push didn't touch.

1. **Review only what changed since the last review.**
   - **Before:** the "Write the PR's diff" step writes `git diff BASE...HEAD`, the whole PR, on every run, including `synchronize`.
   - **After:** on `synchronize`, the workflow finds the newest review whose body starts with the Claude marker, and that review's commit. When that commit is an ancestor of the head, it also writes `delta.diff`: the diff from that commit to the head, leaving out clean merges of `main` (the check the workflow already makes for them).
   - The prompt then says: report only problems on lines `delta.diff` changes, or problems those changes cause elsewhere in the PR. `pr.diff` is context.
   - On the first review, and on `labeled`, `reopened`, `ready_for_review` or a rewritten history (the last reviewed commit isn't an ancestor), it reviews the whole diff, as today.
2. **Raise threads only for what matters.**
   - **Before:** "Report every real problem a maintainer would want fixed or knowingly accepted before merging: bugs, security issues, broken edge cases, missing or wrong tests, and clear departures from the repository's conventions."
   - **After:** "The author's local review (`/pre-push-review`) has already reviewed the whole branch. Open threads only for bugs in code that runs (application code, tests, scripts and workflows), security weaknesses, and how GitHub itself behaves where a local review can't check it. List anything else (docs, comments, conventions) in the review body under **Advisory**, not as threads, so it doesn't hold PR Auto-Merge."
3. **Respect the local review's decisions.**
   - **Before:** the prompt gives only the resolved threads as decisions.
   - **After:** when the PR's author has write access (`OWNER`, `MEMBER` or `COLLABORATOR`), the prompt also gives the PR description's `## Review notes` section, between its <code>&#60;&#33;&#45;&#45; review&#45;notes &#45;&#45;&#62;</code> markers, as decisions. Claude doesn't raise again an accepted finding listed there unless the change brings it back, and the count of accepted security findings is not a finding.
   - A fork author's notes aren't honoured: otherwise anyone could silence a finding by listing it as accepted.

`pr-automerge.yml` needs no change. `reviewCovering` already counts a review of the head commit as covering it, whatever that review read.

### Before merging

- **Real-sandbox check: done for the sandbox; the worktree build follows the merge.** A local Sandcastle run of this branch's code on #84 started real sandboxes for intake and the planner (head mode), and both agents worked. Each sandbox had `GATE_SKIP_REVIEW=1`. It also had `.git/config`, `.git/hooks` and an empty `.git/review` mounted read-only at both the `.git` path and the workspace path, with the rest of `.git` read-write. The build of #84 was deferred by the overlap check, since this PR also changes `README.md`. So the owner accepted the sandbox check as done: #84 stays labelled and ready, and its build after this PR merges is the check of an agent committing in worktree mode.
- **Merge only when no Sandcastle run is in progress, and don't add `sandcastle:follow-up` to this PR.** A Sandcastle host started before the merge doesn't set `GATE_SKIP_REVIEW`, so its sandbox gates would fail the new review check.
