# fix(sandcastle): Keep agent-written code from running on the host

- **Release tag:** `v0.0.89`
- **Source PR:** [#188](https://github.com/mpaulosky/Blazor-Server/pull/188)

## PR description

### Why

Sandcastle let code an agent wrote run on the host, with the user's gh auth, the Docker socket and the home directory. Articles fixed the same problem in mpaulosky/Articles#314. This PR brings that fix to this repo, adapted to its tester, backend, gate checkpoint and critique pipeline.

There were four ways in:

- `publish()` ran `git push` and `gh` from the agent's worktree. Git therefore ran that branch's own `.github/hooks/pre-push`, `scripts/gate.sh` and test code on the host, and agents can edit all of these files.
- Sandcastle mounts the shared `.git` read-write into every sandbox. An agent could set a command in `.git/config` (`core.fsmonitor`, a credential helper), add a hook to `.git/hooks`, or point git at its own config through a `commondir` file or a worktree's `.git` file. The sandbox mounts protected only the skills.
- Fork PRs counted. Anyone can open a PR from a fork with any branch name. One could hold an issue back, or the host could take it for the PR it opened.
- Branch reuse checked only the <code>feature&#124;fix&#124;hotfix&#47;&#60;n&#62;&#45;</code> prefix. `review-prompt.md` passes <code>&#123;&#123;BRANCH&#125;&#125;</code> to `git diff` in the sandbox's shell.

### What changed

- **No git hook runs on the host, and host git reads only this repository's config.** At startup, `main.mts` calls `protectHostGit()` (new `lib/host-safety.mts`). It sets `core.hooksPath=/dev/null` through `GIT_CONFIG_COUNT`/`GIT_CONFIG_*` and pins `GIT_COMMON_DIR` to the repository's `.git`. Both apply to every git command the process starts, including Sandcastle's own. Sandcastle refuses to start if `.git/commondir` exists.
- **The host runs its own git only in the main checkout** (a new `git()` helper in `lib/shell.mts`). It also passes `-c core.hooksPath=/dev/null` and pins `GIT_DIR`, `GIT_COMMON_DIR` and `GIT_WORK_TREE`. Commits are now counted by ref (<code>origin&#47;main&#46;&#46;refs&#47;heads&#47;&#60;branch&#62;</code>), not with `HEAD` in the worktree.
- **`.git/config` and `.git/hooks` are read-only in every sandbox.** The planner, the critique and the builders all get them, mounted next to the skills mounts.
- **The host pushes the exact commit that passed checkpoint 2.** `runGate` reads HEAD before and after the gate, and fails if HEAD moved or can't be read. `publish` pushes <code>&#60;sha&#62;&#58;refs&#47;heads&#47;&#60;branch&#62;</code> from the main checkout, without force. A push that doesn't fast-forward fails rather than drop the work already there. If the push or a `gh` call fails, the host posts git's or gh's error on the issue. It strips colour codes and URL credentials first, and leaves the error out if it looks like it holds a secret.
- **The `sandcastle.gatedHead` marker is gone.** The sandbox no longer writes it to `.git/config`, which is now read-only, and the host's push runs no hook. At startup the host also removes a marker an earlier run left, because the pre-push hook would still skip the gate for that commit. The hook's own check stays as it is, since the hook belongs to the repo-ci-baseline Template. `CLAUDE.md` and `docs/plans/sandcastle-workflow.md` now describe the push with hooks off.
- **Every gh command names the repository** with `--repo`, or with <code>repos&#47;&#60;owner&#62;&#47;&#60;name&#62;</code> for `gh api`, and runs in the main checkout.
- **Pushed commits are scanned for secrets first.** This is ported from IssueTracker. Before the push, the host reads every commit from the base to the commit it's about to push: the messages, authors and committers, the paths, and the added lines. The base is the `origin/main` commit the host resolved before any sandbox started, so moving the ref in the shared `.git` doesn't narrow the scan. Host git runs with replace refs and grafts off (`GIT_NO_REPLACE_OBJECTS`, `GIT_GRAFT_FILE`), so `git log` shows the commits `git push` sends. Added lines are read hunk by hunk, so a line whose content looks like a file header is still scanned. The scan looks for the values `.sandcastle/.env` gives the sandbox, and for anything shaped like a Claude or GitHub token. If it finds one, it comments on the issue without quoting the secret, and nothing is pushed.
- **The host checks a worktree's links before Sandcastle reuses or closes it.** Sandcastle runs git in a worktree both times. If the worktree's `.git` file, its directory under `.git/worktrees` or that directory's `commondir` no longer leads back to this repository, the host doesn't use the worktree. It leaves the worktree for a person to inspect and comments on the issue.
- **Fork PRs are ignored.** This applies when the gate holds issues back, when the critique compares picks with open PRs, and when publish looks for an existing PR.
- **Each picked issue is built once.** `readyPicks` in `lib/plan.mts` drops an issue the planner lists twice.
- **Only standard branch names are reused.** `isIssueBranch` now requires the full <code>feature&#124;fix&#124;hotfix&#47;&#60;n&#62;&#45;&#60;slug&#62;</code> form that `scripts/check-branch-name.sh` allows.

Not ported:

- Articles' merge of main before the check, and its PR title rewrite. Neither is a host-safety change.
- TicketManager's git-config change guard. The read-only mounts already stop the sandbox from changing `.git/config`.

What's left, as in Articles: an agent can still redirect a worktree's own HEAD and index. That changes what git sees in the worktree but runs nothing, unless `extensions.worktreeConfig` is turned on.

### Verification

- `pnpm run check:sandcastle`: the type check and all 189 tests pass. New tests cover:
  - hooks staying off against a real repository, where a control commit does run the hook
  - a real push by commit id that doesn't run a planted `pre-push` hook
  - a planted `.git/commondir` that names a config setting `core.fsmonitor`, where a control run without `GIT_COMMON_DIR` does run it
  - `mainGitDir` refusing a `.git/commondir`
  - worktree link tampering: a redirected `.git`, a redirected `commondir`, and a symlinked directory
  - read-only mounts in every sandbox
  - `runGate` reporting the commit it checked, and failing when HEAD moves or can't be read
  - publishing the commit checkpoint 2 passed on, including after a gate-fixer commit
  - a rejected push being reported on the issue with git's error, with URL credentials stripped
  - removing a leftover `sandcastle.gatedHead`
  - counting commits by ref from the pinned base
  - the secret scan stopping a publish
  - the scan reading the real commit when a replace ref or a grafts file is planted, where control runs without the guard are fooled
  - the scan reading messages, authors, paths and header-like added lines
  - a tampered worktree being left in place
  - fork PR filtering in `openPullRequests` and `openPullRequest`
  - deduplicated picks
  - non-standard branch names being refused, also checked against `scripts/check-branch-name.sh`
- The pre-push gate passed: the lints, the Sandcastle check, the Release build and the test projects.
