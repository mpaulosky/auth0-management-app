# docs(adr): Put one deep seam in front of the Management API

- **Release tag:** `v0.0.5`
- **Source PR:** [#22](https://github.com/mpaulosky/auth0-management-app/pull/22)

## PR description

### Why

User and Role management needs a way for its slices to call Auth0's Management API. The map ticket [What is the Management API seam the Users and Roles slices call?](https://github.com/mpaulosky/auth0-management-app/issues/14) settled it, and the choice departs from the `mpaulosky/Articles` reference that `CLAUDE.md` pointed to, so it gets an ADR.

### What changed

- `docs/adr/0009-one-deep-management-api-seam.md` records the decision:
  - The slices call one `IManagementApi` in `src/UI/ManagementApi/`. It has one method per use case, each returning `Result` and our own records, never SDK types.
  - The token provider, the HTTP client, the SDK adapter and a cache decorator all sit behind it, `internal`.
  - `AddManagementApi()` registers it, binding `Auth0:Management` with `ValidateOnStart`, and each slice's <code>Add&#60;Feature&#62;Feature&#40;&#41;</code> calls it.
  - App rules such as the last-Admin guard stay in the slices' handlers.
  - A 429 that Auth0 still refuses after the SDK's retries comes back as a failed `Result` with the code `ManagementApi.RateLimited`.
  - The adapter pages each Role's members with checkpoint paging, which goes past 1000 Users.
  - The adapter throttles every Management API call through a token bucket that matches Auth0's, sized from `ManagementApiOptions`, with defaults that match the Free tier: 2 a second, burst 2. A cap on calls running at once isn't enough, because Auth0 answers a call over its limit with a 429 at once.
  - The cache is in memory with a short absolute expiry, so changes made outside the app show once an entry expires. The last-Admin guard reads the `Admin` Role's members uncached.
  - After removing `Admin`, the handler re-reads its members, and if none remain it assigns the Role back and returns `Role.LastAdmin`, so two Admins removing each other at once can't leave the Tenant without one.
  - Adapter tests cover a page that returns 429 partway through the fan-out, which fails the whole listing with `ManagementApi.RateLimited`.
  - Test hosts supply placeholder `Auth0:Management:*` settings, because `ValidateOnStart` won't start the app without them.
  - It lists the alternatives it rejected: Articles' SDK client factory, two interfaces, throwing, and the `src/UI/Auth0/` folder name, which clashes with the SDK's namespace.
- `CLAUDE.md` now points at the ADR, mentions the token bucket, and keeps Articles as a reference for the SDK calls only.
- The ADR links the research relatively: the SDK findings at `docs/research/auth0-management-sdk.md`, which #23 adds, and the rate limit findings at `docs/research/auth0-user-search-and-rate-limits.md`, which #24 adds. Both should merge before this PR.
