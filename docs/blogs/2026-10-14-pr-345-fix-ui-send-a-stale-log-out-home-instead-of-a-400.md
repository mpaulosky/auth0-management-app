# fix(ui): Send a stale Log out home instead of a 400

- **Release tag:** `v0.0.152`
- **Source PR:** [#345](https://github.com/mpaulosky/Blazor-Server/pull/345)

## PR description

### Why

Clicking **Log out** in a tab whose session had already ended showed a raw developer message:
*"A valid antiforgery token was not provided with the request. Add an antiforgery token, or disable antiforgery
validation for this endpoint."* The common way to hit it is two tabs: log out in one, then click Log out in the other.

Two things combined:

- A Log out form's antiforgery token is bound to the User signed in when the page rendered. Once that session ended (or
  another User signed in), the logout endpoint's token check failed and it returned an empty 400. The app's log showed
  *"The provided antiforgery token was meant for a different claims-based user than the current user."*
- `UseStatusCodePagesWithReExecute("/not-found")` re-executed that 400 with the request's method, so the NotFound page
  received a POST. Its own antiforgery check failed, and it wrote the message above.

### What changed

- `AuthenticationEndpoints.LogoutAsync` redirects a request whose token fails to `/` and signs nobody out, where it
  returned 400. Nothing changes on the server, so a cross-site POST still can't sign anyone out. Home then shows who, if
  anyone, is signed in.
- `Program.cs` adds a middleware after `UseStatusCodePagesWithReExecute` that disables status code pages for requests
  other than GET and HEAD, so a failing POST keeps its own status instead of becoming the NotFound page's 400. Wrapping
  the re-execute in `UseWhen` was tried first and doesn't work: the re-executed request in the branch matches no
  endpoint, so even a GET loses the NotFound page.
- `LogoutEndpointTests`: the three tests that expected 400 (one a four-case theory) now expect a 302 to `/` with no
  `Set-Cookie`.
- `AppTests.PostUnknownRoute_KeepsStatusWithoutRenderingNotFoundPage`: a POST to an unknown path returns routing's 405
  with an empty body. Before the change it returned 400 with the antiforgery message.

### Verification

- Wrote the tests first; all 7 new expectations failed before the fix and pass after it.
- Reproduced the bug with Playwright against the real Auth0 tenant over HTTPS (sign in, log out in a second tab, click
  Log out in the first), then reran it against the fix: the stale tab lands on Home showing **Log in**.
- `scripts/gate.sh` passes: lint, Release build and every test project.
