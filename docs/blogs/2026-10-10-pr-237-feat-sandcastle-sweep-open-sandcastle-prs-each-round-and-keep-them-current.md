# feat(sandcastle): Sweep open Sandcastle PRs each round and keep them current

- **Release tag:** `v0.0.111`
- **Source PR:** [#237](https://github.com/mpaulosky/Blazor-Server/pull/237)

## PR description

Closes #77

### Why

Nothing acted on a Sandcastle PR after it opened. A PR could:

- fall behind `main`;
- miss its Copilot review;
- close without merging, while its issue stayed open with nothing to say why.

The issue covers the host-only half of the follow-up sweep in `docs/plans/sandcastle-workflow.md` ("Phase 1: Follow-up sweep"):

- finding the PRs that need attention;
- the fixes that need no agent.

The agent passes that fix conflicts, red checks and bot threads come in a later issue.

### What changed

**The sweep (`lib/follow-up.mts`, new).** `followUpPhase()` runs at the start of every round, before the umbrella check and intake (`main.mts`, now "Phase 0: Housekeeping"). A failure is logged and the sweep runs again next round; it never stops a build.

- **Scope.** The sweep acts only on PRs the host published itself. `sweepSkipReason` names the first reason a PR is skipped:
  - from a fork;
  - not into `main`;
  - not on a <code>feature&#124;fix&#124;hotfix&#47;&#123;n&#125;&#45;&#8230;</code> branch that `isIssueBranch` accepts;
  - the issue isn't open and in scope;
  - a draft;
  - labelled `sandcastle:needs-human`;
  - not opened by the host's own login;
  - no <code>&#60;&#33;&#45;&#45; sandcastle&#58;pr &#45;&#45;&#62;</code> marker;
  - truncated by a GraphQL page.

  Each skip is logged, so a PR the sweep ignores still shows up in the run log.
- **Decisions (`decide`):**
  - Logs a `DIRTY` PR as needing a follow-up pass at once. GitHub runs no `pull_request` workflows on a PR it can't merge, so waiting on checks would hide the conflict.
  - Otherwise waits while no checks have reported or any check is running.
  - Once CI completes, logs the PR as needing a pass if it has a red check or an unresolved thread a bot opened, whatever Copilot's state. Neither depends on Copilot reviewing this head, so a dropped request, or a new head from update-branch, can't hide them.
  - Waits while a Copilot request is pending.
  - Re-requests Copilot through `requestReviewsByLogin` (with `union: true`) when CI on the head finished more than 60 minutes ago (`COPILOT_REREQUEST_AFTER_MS`), Copilot hasn't reviewed the head, and no request has been made since the head's first check completed. Because it checks for an earlier request, it re-requests at most once per head, even when GitHub drops the request or a rerun job finishes later.
  - Once the one re-request is spent with no review of the head, the wait says a person needs to ask Copilot, so the stuck state shows in the log.
  - Updates a settled PR that's only `BEHIND` with <code>PUT &#47;pulls&#47;&#123;n&#125;&#47;update&#45;branch</code>, passing `expected_head_sha`, so GitHub refuses if the head moved since the sweep read it.
  - Leaves everything else alone: `CLEAN`, `BLOCKED`, or only human threads open.
  - A check with no completion time can't trigger a re-request.

  Each PR is handled in its own `try`/`catch`, so one failed update doesn't stop the rest.
- **Closed without merging.** The sweep hands an issue back with `sandcastle:needs-human` when all of these hold:
  - the issue is in scope and not already handed back;
  - it has no open same-repo PR;
  - its latest host-published PR closed without merging.

  The comment starts with the issue's wording: "PR #x was closed without merging; remove the label to rebuild." If a person removes the label after that PR closed, the same closed PR doesn't hand the issue back again.

**Starting from `main` on the rebuild (`lib/build.mts`, `lib/branches.mts`).**

- `buildMarkedIssue` calls `host.startFromMain` after it marks the issue `sandcastle:building` and before `createSandbox()`.
- `startFromMain` discards nothing unless a person has removed `sandcastle:needs-human` since the PR closed. This is the same rule the sweep uses. If nobody re-queued the issue (for example, the PR closed after this round's sweep, or the sweep's hand-back failed), it hands the issue back and stops the build, with the work intact.
- When the issue's latest PR closed without merging on the branch being built, `discardClosedWork` first makes sure the repository has the closed head. If its branch was deleted with the PR, it fetches <code>refs&#47;pull&#47;&#60;n&#62;&#47;head</code>, which GitHub keeps, and throws if the head still can't be found.
- It then deletes each of these refs that holds the closed PR's work, in this order:
  1. the local branch;
  2. <code>refs&#47;remotes&#47;origin&#47;&#60;branch&#62;</code>;
  3. origin's branch, via <code>git push &#45;&#45;force&#45;with&#45;lease&#61;&#60;branch&#62;&#58;&#60;sha&#62; origin &#58;&#60;branch&#62;</code>.
- A ref holds the closed PR's work when its merge base with the closed head is a commit `main` doesn't have. That covers a ref that contains the head, one that lags behind it (the local branch sits where the sandbox pushed, and an update-branch or a commit made on GitHub moves the PR past it), and one that has diverged from it.
- Any other ref is kept, so a fresh attempt's commits survive. Nothing is deleted when `main` already contains the closed head.
- The local branch goes first because git refuses to delete it while a worktree has it checked out, and failing there leaves origin's branch untouched.
- A throw stops the build without counting it as a failed attempt, so the build never runs on top of the old work.

**Marker and GitHub reads (`lib/config.mts`, `lib/github.mts`).**

- `publish` now starts every PR body with `PR_MARKER`. PRs opened before this change, including this one, don't carry it, so the sweep never acts on them.
- New helpers:
  - `openPullRequestsForSweep`: one GraphQL query paged by hand. It normalises check runs and status contexts, and marks a PR truncated when any nested list has another page.
  - `closedPullRequests`.
  - `requestCopilotReview`.
  - `updatePullRequestBranch`.
  - `signedInHostLogin`: cached per runner.
  - `isCopilot`: accepts all three spellings GitHub uses for Copilot's review account.

**Architect.** This is the first build where the planner picked the architect role. Its design note is posted on #77 ([comment](https://github.com/mpaulosky/Blazor-Server/issues/77#issuecomment-6094589535)).
