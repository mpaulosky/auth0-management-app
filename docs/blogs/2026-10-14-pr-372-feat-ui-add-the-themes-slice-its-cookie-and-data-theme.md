# feat(ui): Add the Themes slice, its cookie and data-theme

- **Release tag:** `v0.0.158`
- **Source PR:** [#372](https://github.com/mpaulosky/Blazor-Server/pull/372)

## PR description

Closes #363

### Why

A Generated App needs to remember a visitor's Theme (Light, Dark or System) and render it from the first paint, without JavaScript and without a flash of the wrong Theme.
This branch adds the server side of that, as described in `docs/plans/theme-and-palette.md`: a `theme` cookie, an endpoint that sets it, and `data-theme` on <code>&#60;html&#62;</code>.
It adds no control yet. The nav control comes in the next issue, and Palette follows after that.

### What changed

- A new Themes slice, `src/UI/Components/Features/Themes/`:
  - `Theme`, an enum with System, Light and Dark.
  - `ThemeExtensions`, a C# 14 `extension(Theme)` block with `FromCookie` and `ToDataTheme`.
    `FromCookie` is ordinal and case-sensitive, so any value other than `light` or `dark` means System.
  - `SetThemeCommand`, `SetThemeCommandValidator` (FluentValidation) and `SetThemeHandler`.
    The validator accepts exactly `light`, `dark` and `system`.
    The handler returns a <code>Result&#60;Theme&#62;</code>, or a failed result with `ResultErrorCode.Validation` and the code `Theme.Unknown`.
  - `ThemeEndpoints`, with `POST /theme`. It checks the antiforgery token itself, and a token that fails redirects to the local `returnUrl` and changes nothing.
    A valid choice sets the `theme` cookie, or deletes it for System, and answers 302 to the `returnUrl`.
    An unknown value answers 400 ProblemDetails with `code` `Theme.Unknown`.
    `GET` and `HEAD` answer 405 with `Allow: POST`.
  - `ThemeFeature.AddThemeFeature()`, which registers the validator and handler as singletons.
- The cookie lasts one year and has `SameSite=Lax`, `Secure`, `HttpOnly` and `Path=/`.
  It's marked essential because it's a display preference.
- `Program.cs` calls `AddThemeFeature()` and `MapThemeEndpoints()`.
- `App.razor` reads the cookie through the cascading `HttpContext` and renders `data-theme="light"` or `data-theme="dark"` on <code>&#60;html&#62;</code>.
  For System, or an unknown value, it renders no attribute, so the OS decides.
- `UI.csproj` now references `FluentValidation`.
  The package was already versioned in `Directory.Packages.props`, and the coding standards require it for request validation.
- The code follows the plan. There was no design note for this issue.

### Verification

- `tests/UI.Tests.Unit/Components/Features/Themes/ThemeExtensionsTests.cs` pins these mappings:
  - `FromCookie`: `light` and `dark` map to Light and Dark. `null`, empty, `system`, wrong-case and unknown values map to System.
  - `ToDataTheme`: each Theme maps to `light`, `dark`, or `null` for System.
- `SetThemeCommandValidatorTests.cs` checks that the three values are accepted. It checks that unknown, empty, missing and wrong-case values fail with the code `Theme.Unknown`.
- `SetThemeHandlerTests.cs` pins the Theme returned for each valid value.
  It also pins the failed result for an invalid command: `ResultErrorCode.Validation`, with `Details` equal to `Theme.Unknown`.
- `tests/UI.Tests.Integration/Components/Features/Themes/ThemeRenderingTests.cs` checks that a `dark` or `light` cookie renders the matching `data-theme`.
  It checks that `system` and an unknown value render none.
  The existing `AppTests` already pins that a request with no cookie renders none.
- `ThemeEndpointTests.cs` pins the endpoint:
  - A valid post sets the cookie with each attribute and answers 302 to the `returnUrl`.
  - `system` deletes the cookie.
  - An unknown value answers 400 `application/problem+json` with `code` `Theme.Unknown`, and sets no cookie.
  - A missing or invalid token redirects without setting a cookie.
  - A non-local `returnUrl` redirects to `/`.
  - `GET` answers 405 with `Allow: POST`.
- `tests/Architecture.Tests/UiTests.cs` now requires the slice rule to find Themes, with no cross-slice dependencies.
- `scripts/gate.sh` passed on the final branch. It ran the lints, the Release build and every test project, including the E2E tests.
