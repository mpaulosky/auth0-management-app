# fix(UI): Install the pnpm packages on a local build when the Tailwind CLI is missing (#409)

- **Release tag:** `v0.0.171`
- **Source PR:** [#410](https://github.com/mpaulosky/Blazor-Server/pull/410)

## PR description

### Why

A fresh clone or worktree has no `node_modules`, so `dotnet build` failed in `UI.csproj`'s `BuildTailwindCss` target ("The Tailwind CSS CLI isn't installed in src/UI/node_modules"). That failed the pre-push gate twice during the repo-ci-baseline re-Apply round (mpaulosky/dotfiles#217). CI never hits it, because `.github/ci/prepare.sh build` installs the packages first.

### What changed

- `src/UI/UI.csproj`: a new `EnsurePnpmPackages` target runs before `BuildTailwindCss`. When the Tailwind CLI's `package.json` is missing, it runs `pnpm install --frozen-lockfile` at the repository root, where the lockfile and workspace are. CI and design-time builds skip it. TicketManager and Articles do the same in their `Web.csproj`.

### Verification

- In a fresh worktree with no `node_modules`, `dotnet build Blazor-Server.slnx --configuration Release -warnaserror` ran the install and then succeeded, with 0 warnings.
- A second build didn't run the install again.
- With `CI=true`, the install didn't run.
- The pre-push gate (`scripts/gate.sh`) passed on `dfe210b`.

Fixes #409
