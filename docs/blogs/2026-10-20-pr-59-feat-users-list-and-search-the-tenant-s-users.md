# feat(Users): List and search the Tenant's Users

- **Release tag:** `v0.0.20`
- **Source PR:** [#59](https://github.com/mpaulosky/auth0-management-app/pull/59)

## PR description

Closes #35

### Why

An Admin had no way to find a User in the Tenant from the app.
The plan for User and Role management starts with the Users page at `/admin/users`, so this change adds its left side: a search box and a paged list of the Tenant's Users.
Only Admins can open it.
The right-hand side only asks the Admin to pick a User for now; showing that User comes in the next issue.

### What changed

- A new `Users` slice in `src/UI/Components/Features/Users/`:
  - `UsersPage` at `/admin/users`, rendered with `InteractiveServer` and protected by <code>&#91;Authorize&#40;Policy &#61; ApplicationConstants&#46;AdminPolicy&#41;&#93;</code>.
    It has a **Users | Roles** tab switch, made of ordinary links to `/admin/users` and `/admin/roles`, and its content sits inside `ManagementApiErrorBoundary`.
    Until the Roles page ships in a later issue, the Roles tab leads to the NotFound page. The owner accepted that dead link, because issue #35 asks for the tab.
  - `UserListPane` holds the search box ("Search name or email") and the list.
    Typing searches after a 400 ms pause, timed by the injected `TimeProvider`, and Enter searches at once.
    A newer search cancels the one still running, and every new search goes back to page 1.
    Each row shows the User's picture (only an `http` or `https` URL) or their initials, their name and their email, and an **Admin** badge when they hold `Admin`.
    The pager reads "‹ Prev", "Page x of y · N Users" and "Next ›".
    Over 1,000 matches, a note says Auth0 shows only the first 1,000.
    `User.SearchInvalid` and `User.SearchTooBroad` show in an Error `Alert`.
    `ManagementApi.RateLimited` shows in a Warning `Alert`, and the search box and the last list stay as they were.
  - `UsersUrlState` reads `q`, `page` and `user` from the URL once, when the page starts.
    A `page` below 1 or not a number counts as page 1.
    `UsersPage.razor.js` writes the state back with `history.replaceState`, so searching never adds browser history entries and never calls `NavigationManager.NavigateTo`.
  - `SearchUsersQuery` and `SearchUsersQueryValidator`.
    A query longer than 100 characters after trimming, or a page below 1, fails with `User.SearchInvalid`.
  - `UserSearchQueryBuilder` lower-cases and trims the text, escapes Lucene's special characters, and turns each run of whitespace into one escaped space.
    It builds <code>email&#58;&#60;t&#62;&#42; OR name&#58;&#60;t&#62;&#42; OR given&#95;name&#58;&#60;t&#62;&#42; OR family&#95;name&#58;&#60;t&#62;&#42;</code>, or no query at all when the box is empty.
  - `UserPaging` sets 25 Users a page and counts the reachable pages as `max(1, min(ceil(total / 25), 40))`.
  - `SearchUsersHandler` validates the query and limits the page to 40 before sending any request.
    When the response shows the page is past the last one, it asks for the last reachable page instead.
    It finds the Admins with one `ListRolesAsync` and one `ListRoleMembersAsync` for `Admin`, never one request per User.
  - `AddUsersFeature()` registers the validator and the handler and calls `AddManagementApi()`. `Program.cs` calls it.
- The AppHost now reads `Auth0:Management:Domain`, `:ClientId` and `:ClientSecret` from configuration and passes them to WebApp, since WebApp now checks them on start.
  They stay separate from the sign-in application's settings.
- `README.md` says the Management API settings are now needed to start the app. `CLAUDE.md` describes the new slice.
- A cleanup pass after the feature commits changed no behaviour.
  `UserPaging` now works out `MaxPage` from `SearchCap`, the handler explains its null-forgiving `Value!` uses, and the pane's key handler is named `OnKeyDownAsync`.
  The AppHost forwarding tests share one setup helper.

No design note was written for this issue.
No NuGet package was added. `UI.Tests.Integration` now references NSubstitute, which `Directory.Packages.props` already listed.
