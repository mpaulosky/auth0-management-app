# feat(sandcastle): Give the developer roles build, test and stub steps for both stacks

- **Release tag:** `v0.0.99`
- **Source PR:** [#208](https://github.com/mpaulosky/Blazor-Server/pull/208)

## PR description

### Why

Sandcastle's developer roles were written for .NET only. The tester built with `dotnet build`, stubbed with
`NotImplementedException`, and put tests in the .NET test project. The backend developer and gate-fixer listed only
xUnit's `Skip` as a way to weaken a test. Every Sandcastle issue so far changes the TypeScript in `.sandcastle/`, so
agents had to translate those steps themselves each run. The Blazor app, planned in future issues, will bring .NET work,
so the prompts need both stacks rather than a switch from one to the other.

### What changed

- `roles/shared-rules.md` has a table with each stack's paths, build command and test command: `dotnet build` and
  `dotnet test --project` for .NET; `pnpm exec tsc --noEmit -p .sandcastle` and `pnpm exec tsx --test` for Sandcastle's
  TypeScript. It also points at each stack's standards: `docs/CODING_STANDARDS.md` and `.claude/rules/sandcastle.md`.
- `roles/tester.md`:
  - Tests go in the mirroring test project for .NET, or in <code>&#60;module&#62;&#46;test&#46;mts</code> beside the module for TypeScript.
  - Stubs throw `NotImplementedException` in .NET, or `new Error("Not implemented")` in TypeScript.
  - It builds and runs tests with the stack's commands from the shared rules.
- `roles/backend.md` and `roles/gate-fixer.md` forbid skipping or todoing a test in any form: xUnit's `Skip`,
  `SkipUnless`, `SkipWhen`, `Explicit = true` and `Assert.Skip*`, and `node:test`'s `.skip`, `.todo`, <code>&#123; skip &#125;</code>, <code>&#123; todo &#125;</code>, `t.skip()` and `t.todo()`.
- The tester's and backend's skill lists now say they're for .NET work. The skills are unchanged.
- `lib/role-prompts.test.mts` has new tests for each of these, so a later edit can't quietly drop one stack.

`.claude/rules/sandcastle.md` arrives in #207. Until that merges, the prompts point at a file that doesn't exist yet.

### Verification

- The new tests failed before the prompt changes and pass after. `pnpm run check:sandcastle` passes (203 tests).
- `markdownlint-cli2` with `.sandcastle/.markdownlint-cli2.jsonc` passes on every role prompt, and the pre-push gate
  passed.
