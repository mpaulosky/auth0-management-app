## ci: Fail Test Report Summary when the test matrix fails

- **Release tag:** `v0.0.35`
- **Source PR:** [#35](https://github.com/mpaulosky/Blazor-Server/pull/35)

### PR description

main's `main-rules` ruleset only required **Build Solution**, so PR #31 auto-merged about 36 seconds after its branch was updated, while its test jobs were still running.

## Ruleset change (already applied)
Required status checks on main (strict, integration: GitHub Actions):
- Build Solution (already required)
- Test Report Summary
- markdownlint
- yamllint
- Analyze (csharp)

Each of these runs on every PR to main with no path filter or job-level condition, so none can go missing and block a merge. The `Tests: …` matrix jobs aren't listed because their names depend on which test projects are discovered. `.NET code metrics` is left out because it fails on every push to main: the bot isn't allowed to push its `create-pull-request/patch` branch.

## Workflow change
`Test Report Summary` stands in for the test matrix, but it only wrote FAILED to the job summary and still passed. It now exits non-zero when build, discovery or the test matrix fails or is cancelled. A skipped matrix still passes, whether because there are no test projects or because the PR is from Dependabot.
