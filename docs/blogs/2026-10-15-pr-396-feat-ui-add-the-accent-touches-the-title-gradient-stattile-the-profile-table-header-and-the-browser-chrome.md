# feat(ui): Add the accent touches: the title gradient, StatTile, the Profile table header and the browser chrome

- **Release tag:** `v0.0.166`
- **Source PR:** [#396](https://github.com/mpaulosky/Blazor-Server/pull/396)

## PR description

Closes #389

### Why

The Palette already tints the Generated App's surfaces and borders, but the hue barely shows anywhere else.
On pages whose header sits straight on the tinted page, such as Profile and Admin, the eyebrow pill blended into the background.
The Profile table header's colours failed WCAG AA contrast for the red and pink hues in the prototype.
The browser's own controls and scrollbars kept their default blue whatever Palette the visitor picked.
This change adds the accent touches from `docs/plans/palette-tint.md`, so every visitor sees their chosen Palette in the page titles, the stat tiles, the Profile table and the browser chrome.

The review of #392 also found that two of the architecture text guards matched too loosely, so this branch tightens them.

### What changed

- `PageHeader`: the <code>&#60;h1&#62;</code> gets a gradient text fill (`bg-linear-to-r from-accent-800 to-accent-500 bg-clip-text text-transparent`, `dark:from-accent-100 dark:to-accent-400`).
  The eyebrow pill moves to `bg-accent-200 text-accent-800` in Light. Its Dark classes don't change.
- `StatTile`: the tile gets an accent left edge and fill (`border-l-4 border-l-accent-500 bg-accent-50`, `dark:border-l-accent-500 dark:bg-accent-900/60`).
  The value is now `text-accent-700 dark:text-accent-300`. The label keeps `text-slate-600 dark:text-slate-300`.
- The Profile table header is now `bg-accent-200 text-accent-800 dark:bg-accent-800 dark:text-accent-200`.
- `app.tailwind.css` adds a `:root` rule in `@layer base`, after the Palette rules.
  It sets `accent-color` from `accent-600`, and `scrollbar-color` from `accent-500` on `accent-100`, with `accent-400` on `accent-950` under the `dark` variant.
  In the compiled `app.css` the Dark value appears under both the explicit `data-theme=dark` selector and the `prefers-color-scheme` media query.
- `UiRestyleTests`: `DarkTextClassPattern` now has `:` in its lookbehind, so `hover:dark:text-white` no longer counts as a resting Dark text colour.
  `SlateTextClassPattern`'s variant chain now matches digits and one bracketed argument per variant (`2xl:`, <code>data&#45;&#91;open&#93;&#58;</code>, <code>aria&#45;&#91;current&#61;page&#93;&#58;</code>, <code>&#91;&#38;&#95;a&#93;&#58;</code>).
  As a result, <code>dark&#58;data&#45;&#91;open&#93;&#58;text&#45;slate&#45;600</code> is checked as Dark text.

No architect's design note was written for this issue, so there's nothing to depart from.

### Verification

- `tests/UI.Tests.Unit/Components/Shared/PageHeaderTests.cs`: checks the <code>&#60;h1&#62;</code>'s gradient classes and the eyebrow pill's `bg-accent-200` and `text-accent-800`.
- `tests/UI.Tests.Unit/Components/Shared/StatTileTests.cs`: checks the tile's left edge and fill classes, the label's slate text classes and the value's accent text classes.

- `tests/UI.Tests.Unit/Styles/AppTailwindCssTests.cs`: checks that `accent-color` and the Light `scrollbar-color` are in the bare `:root` rule.
  It also checks that the Dark `scrollbar-color` is in that rule's `@variant dark` block.
  A third test checks that the rule comes after the last Palette rule.
  A review commit tightened the first two tests: before, they only checked that each declaration appeared somewhere in the file.
  With the Dark value moved out of the block, the tightened test fails and the old one passed.
- `tests/Architecture.Tests/UiRestyleTests.cs`: direct tests show that `DarkTextClassPattern` rejects `hover:dark:text-white` but still matches `dark:text-white`.
  Another shows that `SlateTextClassPattern` records `dark:` in the variants of <code>dark&#58;data&#45;&#91;open&#93;&#58;text&#45;slate&#45;600</code>.
  As the commit records, `text-slate-600 hover:dark:text-white` and <code>dark&#58;data&#45;&#91;open&#93;&#58;text&#45;slate&#45;600</code> were planted in `Card.razor`.
  The markup guards passed with the old patterns and failed with the new ones. The plants were then removed.
- `scripts/gate.sh` passed: lint, a Release build, and every test project, including the E2E tests.
  The E2E Auth0 sign-in test skipped itself, because only placeholder Auth0 settings were configured.
