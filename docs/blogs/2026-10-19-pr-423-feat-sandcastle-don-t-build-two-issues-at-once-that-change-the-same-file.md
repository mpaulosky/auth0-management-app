# feat(sandcastle): Don't build two issues at once that change the same file

- **Release tag:** `v0.0.176`
- **Source PR:** [#423](https://github.com/mpaulosky/Blazor-Server/pull/423)

## PR description

Closes #421

### Why

Two Sandcastle issues that change the same file could be built at the same time. Once the first PR merged, the second conflicted with main and had to be repaired by hand.
That happened in mpaulosky/dotfiles, whose `.sandcastle/` is ported from this one: two PRs both rewrote the merge-main code in `.sandcastle/lib/build.mts`, and the second went `DIRTY`.
Until now only the critique agent looked for overlap, and it had gaps. It guessed which files each pick would change, and its prompt says to keep a pick when in doubt.
It saw only the PRs of its own queue, so a PR from another queue or from a person was invisible to it.
Nothing in code backed it up when it missed an overlap.

### What changed

- The plan schema (`.sandcastle/lib/plan.mts`) has an optional `files` list per pick: the paths the planner expects the issue to change.
  `plan-prompt.md` now asks for this list, and its example output includes one.
- New `.sandcastle/lib/overlap.mts`: `deferOverlaps` runs in code after the planner and before the critique, with no agent involved.
  It goes through the picks in the planner's order and defers any pick whose `files` share a path with a pick kept earlier, or with an open PR into main.
  The PR can come from any author or queue. Fork PRs are left out so an outsider can't hold issues back.
- A pick with no `files`, or an empty list, is treated as touching anything. It's built only when it's the round's only pick and no PR into main is open.
- Each deferred pick gets one comment naming the shared file and the issue or PR it waits on, and is recorded as "deferred" in the run report.
  A pick deferred behind an issue built this round is also linked as blocked by that issue.
  A pick deferred behind a PR can't be linked, since a PR can't be a native blocker. Instead `main.mts` holds it back for the rest of the run, so it isn't picked and commented on again every round.
- A failed GitHub read in the check throws, so nothing is built on an overlap the host couldn't check.
- `.sandcastle/lib/github.mts` adds `openPullRequestsIntoMain`, which lists open PRs whose base is `main`. It shares one `gh pr list` helper with `openPullRequests`.
- `main.mts` calls the check as Phase 1a. The critique still runs on the picks that are left, to catch dependencies and overlaps of modules rather than paths.
- `docs/plans/sandcastle-workflow.md` describes the overlap check, the planner's `files` field and the new module.
- No design note was written for this issue, so there's nothing to depart from.

### Verification

- `.sandcastle/lib/overlap.test.mts` (new), with tests that pin:
  - of two picks naming the same file, only the first is built, and the comment names the file and the earlier issue;
  - a pick naming a file an open PR into main changes is deferred, and the comment names the file and the PR;
  - a pick deferred behind a PR isn't linked as blocked;
  - disjoint picks are all built, with nothing written to GitHub;
  - a pick with no `files`, or an empty list, is deferred when another pick is in the round, and also when any PR into main is open;
  - a pick with no `files` is built when it's the only pick and no PR is open;
  - a later pick is compared only with picks that were kept, in the planner's order;
  - each deferral is recorded as "deferred" in the run report.
- `.sandcastle/lib/plan.test.mts` checks that `plan-prompt.md` asks for a `files` list per pick.
- `.sandcastle/main.test.mts` checks that `main.mts` calls `deferOverlaps` after `planRound` and before `critiqueRound`.
- `scripts/gate.sh` passed on the final commit: the Markdown lint, the Sandcastle check (type-check and all 1,102 tests), the Release build and every .NET test project.
