# chore(claude): Make Claude Code the repo's agent setup

- **Release tag:** `v0.0.60`
- **Source PR:** [#118](https://github.com/mpaulosky/Blazor-Server/pull/118)

## PR description

Before: the repo's agent guidance was written for Copilot (`.github/copilot-instructions.md`, `.github/instructions/`, `.github/agents/`), which Claude Code never reads. Claude only saw the vendored .NET skills, and permissions lived in a gitignored `settings.local.json`.

After: Claude Code is the authoring agent, and Copilot stays as the independent PR reviewer the ruleset and `pr-automerge.yml` already rely on.

What changed:

- **`CLAUDE.md`** (new) imports `CONTEXT.md` and the coding standards, and lists the build, test, `pnpm run check:sandcastle` and `scripts/gate.sh` commands, branch and commit rules, and the `[skip-release]` marker.
- **`.claude/rules/`**: the five Copilot instruction files moved here with `paths:` frontmatter, so each loads only for matching files (`git-commit.md` always). Copilot-only wording and the chat "Response Style" section are gone.
- **`.claude/settings.json`** (new, shared): allows the build, test, lint and gate commands; denies reading `.sandcastle/.env`.
- **`docs/CODING_STANDARDS.md`**: moved from `.sandcastle/`, since every tool and contributor uses it. Sandcastle prompts, `CONTRIBUTING.md`, the README and the code-review skill point at the new path.
- **Code review**: the `code-review` skill moved to `.claude/skills/`. `.github/copilot-instructions.md` is now generated from it by `scripts/sync-copilot-review.sh`, so Copilot and Claude review against one checklist. `scripts/gate.sh` and a new `copilot-review-sync` job in `lint-markdown.yml` fail when the two drift; `gate.test.sh` covers the synced and drifted cases.
- **Removed**: the GPT-4.1 Beast agent and the Codex `openai.yaml` skill metadata.
- **`.gitignore`**: ignores `.claude/worktrees/`, drops the unused `content/` rules and duplicate entries, and narrows `*.txt` to `build-log.txt` (the only file it matched).

Not changed: `CODE_METRICS.md` stays at the root, because the pinned metrics action always writes it into the directory it scans.

Heads-up: with the `content/` negation gone, `appsettings.Development.json` is ignored everywhere; the UI work will need a `!` exception if the template should ship one.

Verified locally: `scripts/gate.sh` passed (YAML, Markdown, workflow and shell lint, the new sync check, Sandcastle check, Release build, all test projects), and `scripts/tests/gate.test.sh` passed 21/21.
