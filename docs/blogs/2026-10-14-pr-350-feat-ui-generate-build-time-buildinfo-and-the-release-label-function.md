# feat(ui): Generate build-time BuildInfo and the Release label function

- **Release tag:** `v0.0.153`
- **Source PR:** [#350](https://github.com/mpaulosky/Blazor-Server/pull/350)

## PR description

Closes #348

### Why

The Generated App has no way to say which build is running.
A User or maintainer looking at a deployed site can't tell which Release it is, or how far past that Release the code has moved.
Finding out at runtime would mean calling the GitHub API or running `git` on the server, and neither belongs in a web app.
This change records that information when the app is compiled, so a later change can show it in the footer.

### What changed

- `src/UI/UI.csproj` has a new `GenerateBuildInfo` target.
  It runs after Source Link's `InitializeSourceControlInformation` and before compilation, and writes `BuildInfo.g.cs` into the intermediate output folder.
  The file holds an internal `BuildInfoConstants` class with three constants:
  the output of <code>git describe &#45;&#45;tags &#45;&#45;long &#45;&#45;match &#34;v&#91;0&#45;9&#93;&#42;&#34;</code>, the full commit SHA (`SourceRevisionId`) and the repository URL (`PrivateRepositoryUrl`).
- The `git describe` step ignores its exit code and keeps its error output at low importance.
  A missing `git`, a missing `.git` folder or a repository with no `v*` tags leaves the Release empty, and the build still passes under `-warnaserror`.
  Each value is escaped before it goes into a C# string literal.
- Design-time builds (IDEs) skip the target, as the issue asks.
  Going beyond the issue, they still compile the file the last real build wrote, when there is one, so an IDE doesn't report `BuildInfoConstants` as missing.
- A new `BuildInfo` record in `src/UI/Components/Layout/` carries `Release`, `Commit` and `RepositoryUrl`.
  `Program.cs` builds it from the generated constants and registers it as a singleton, so tests can register their own values.
- A new `ReleaseLabel` record in the same folder has `FromDescribe`, which turns the `git describe` output into the label text and its link.
  It reads the output from the end, so a tag with its own hyphens (`v1.0.0-rc.1`) stays whole.
  An exact Release shows the bare tag, a later commit shows <code>&#60;tag&#62; &#43;&#60;count&#62;</code>, and empty or unreadable output shows `no release`, linking to the releases list.
- `CONTEXT.md` defines the **Release** domain term.
- The review pass found nothing to simplify, so it changed no code.
  No architect's design note was written for this issue.

One difference from the issue's wording: with `git` missing from `PATH` but a `.git` folder present, the Release is empty but the commit and repository URL are still filled in.
Source Link reads `.git` itself, without the `git` program.
Outside a git checkout, all three values are empty, as the issue expects.

### Verification

- `tests/UI.Tests.Unit/Components/Layout/ReleaseLabelTests.cs`: one <code>&#91;Theory&#93;</code> covering every row of the issue's label table:
  an exact Release, one commit past it, a hyphenated tag and empty output.
- `tests/UI.Tests.Integration/Components/Layout/BuildInfoRegistrationTests.cs`: `BuildInfo` resolves from the app's container through <code>WebApplicationFactory&#60;Program&#62;</code>,
  and resolves to the same instance twice.
  It doesn't check the actual tag or SHA, which differ from one checkout to another.
- `tests/Architecture.Tests/ReleaseDomainTermTests.cs`: `CONTEXT.md` contains the **Release** entry word for word.
- These tests were committed failing before the code that makes them pass, and are unchanged since then.
- No automated test covers building without `git` or outside a git checkout, because a test run can't rebuild the app under those conditions.
  The commit that adds the target records checking it by hand: a `v1.0.0-rc.1` tag one commit back gives <code>v1&#46;0&#46;0&#45;rc&#46;1&#45;1&#45;g&#60;sha&#62;</code>,
  a copy of the tree without `.git` builds with all three values empty, and a build with `git` off `PATH` passes with an empty Release.
- `scripts/gate.sh` passed on the final branch: Markdown lint, a Release build and every test project.
