# fix(sandcastle): Keep one bad intake verdict from costing the batch, and post intake's text as plain text

- **Release tag:** `v0.0.106`
- **Source PR:** [#225](https://github.com/mpaulosky/Blazor-Server/pull/225)

## PR description

### Why

Claude's review of #222's final push, posted 41 seconds after the PR merged, found three problems in intake
(`.sandcastle/lib/intake.mts`) (#224):

- **One bad verdict cost the whole batch.** The schema rejected a numeric `id`, which is natural because the issue JSON
  gives `number` as a number, and a verdict without `bug`. Either one made Sandcastle reject the whole <code>&#60;intake&#62;</code> block,
  so no issue was judged. Intake also sent every unjudged issue in one call, so on a large backlog, such as the first run
  after #222, one bad or truncated answer cost all of them.
- **A valid verdict could be dropped.** An issue counted as judged before a needs-info verdict with no questions was
  ignored. So a valid verdict for the same issue later in the block was dropped as a duplicate.
- **The model's text reached the issue comment as Markdown.** The reason and questions come from a model that read
  untrusted issue text. A stray `` ``` `` could swallow the rest of the comment, including the re-queue instructions.
  `@login` notified that user, `#123` cross-referenced another issue, and a leading `-` or `#` started a list or a
  heading.

### What changed

- **A lenient schema where a slip is harmless.** A numeric `id` is taken as a string, and a missing `bug` means
  `false`. An unknown verdict, an id of any other type, or a missing `verdicts` list is still rejected.
- **A batch per round.** `intakeRound` judges at most `INTAKE_BATCH_SIZE` (10, in `config.mts`) issues a round, and logs
  how many wait for a later round or run.
- **Ignored verdicts don't count.** The no-questions check now runs before the issue is recorded as judged.
- **Plain text in comments.** The new `plainText` is applied to the reason in both comments and to every question. It:
  - keeps the text to one line;
  - escapes backslashes and backticks;
  - breaks `@` mentions and `#` references with a zero-width space;
  - escapes a leading list, heading or quote marker. A leading number is escaped only when it's followed by `.` or `)`
    and a space, so "2.0 or 3.0?" is left alone.

### Verification

New tests, in `.sandcastle/lib/intake.test.mts`, by acceptance criterion:

- `gives Sandcastle a schema that takes a numeric id as a string and a missing bug as false`. This checks the parsed
  value, against the schema object `intakeRunner` hands Sandcastle. The two rejection cases this replaces are removed.
- `judges at most INTAKE_BATCH_SIZE issues a round, and logs how many wait`
- `applies a valid verdict that follows an ignored needs-info verdict with no questions`
- `describe("intake's comments")`:
  - `posts the ready comment's reason / the needs-info comment's reason / a needs-info question without a code fence,
    mention or cross-reference`, using a text with `` ``` ``, `@someone`, `#123` and `owner/repo#45`;
  - `keeps a reason with line breaks on its one line`;
  - `escapes a question that starts with -`, and the same for `#` and `>`.

All 10 failed before the fix. `pnpm run check:sandcastle` passes (379 tests), and the pre-push hook ran
`scripts/gate.sh`.
