# fix(sandcastle): Name bug branches fix/ rather than hotfix/

- **Release tag:** `v0.0.87`
- **Source PR:** [#183](https://github.com/mpaulosky/Blazor-Server/pull/183)

## PR description

### Why

Sandcastle named every `bug` issue's branch <code>hotfix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>. The branch standard in docs/PROCESS.md uses <code>fix&#47;&#123;issue&#125;&#45;&#123;slug&#125;</code> for a bug fix and keeps `hotfix/` for an urgent fix, and no label in this repo marks a fix as urgent. So Sandcastle's bug branches were labelled urgent when they weren't.

### What changed

- `.sandcastle/lib/branches.mts`: an issue with the `bug` label now gets <code>fix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>; every other issue still gets <code>feature&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>. Sandcastle never names a `hotfix/` branch itself.
- The existing-branch lookup (`isIssueBranch`, and the `git ls-remote` that lists origin's issue branches) recognizes `feature/`, `fix/` and `hotfix/`, so an in-flight `hotfix/` branch keeps being reused, and so does a `fix/` branch. The open-PR check in `gate.mts` uses the same lookup, so it now holds back an issue whose open PR comes from a `fix/` branch; only its comment changed.
- `docs/plans/sandcastle-workflow.md`: the label table, Phase 4's naming rule, the follow-up sweep's scope and the planned `workflow_run` trigger say `fix/` for bugs and include `fix/` heads, so a sweep or trigger built from the design doesn't skip Sandcastle's bug-fix PRs.
- `.sandcastle/lib/branches.test.mts`: bugs map to `fix/`, existing `fix/` and `hotfix/` branches are reused, `isIssueBranch` has its own tests, and generated names are checked against `scripts/check-branch-name.sh` rather than a copied regex.
- `.github/ci/gate-checks.sh`: the Sandcastle tests also run when `scripts/check-branch-name.sh` changes, so tightening the branch standard reruns the test that checks Sandcastle's names against it.
