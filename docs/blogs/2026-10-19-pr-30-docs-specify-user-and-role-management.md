# docs: Specify User and Role management

- **Release tag:** `v0.0.10`
- **Source PR:** [#30](https://github.com/mpaulosky/auth0-management-app/pull/30)

## PR description

### Why

The [Manage Users and Roles](https://github.com/mpaulosky/auth0-management-app/issues/11) map has settled every decision about the feature. Sandcastle builds only from issues with checkable criteria, so those decisions need to be written down in one place before the issues can be filed.

### What changed

- **`docs/plans/user-role-management.md`**, the spec. It covers:
  - the pages and routes
  - the Management API seam and its options, with the client-side rate limiter
  - search, paging and the cache
  - Profile Fields
  - Roles on a User and the last-Admin guard
  - creating a Role
  - the failure catalogue and where each failure shows
  - logging and the audit trail
  - testing, offline and against the testing Tenant, with the owner's Tenant setup checklist
  - the twelve implementation issues, in build order with their blockers

  Each section links the map ticket that holds the reasoning.
- **ADR 0010:** only `/admin/users` and `/admin/roles` render with `InteractiveServer`, and every other page, `/admin` included, stays static. Because the `Router` stays static, those pages keep their state in the URL with `history.replaceState` rather than `NavigateTo`.
- **Amendments to ADR 0009**, to match what the spec settled:
  - Two more seam methods, both never cached, for the last-Admin guard: `UserHoldsRoleAsync(userId, roleId)` checks that the User holds `Admin` at all, so removing it from someone who doesn't is a no-op, and `CountRoleMembersAsync(roleId, atMost)` counts the Admins before and after the removal.
  - `User.LastAdmin` as the one code for both the refusal and the restore. The ADR said `Role.LastAdmin`.
  - Role member listing stops at 1000 members and says so with `RoleMembers.Truncated`.
  - The client-side limiter takes one token per HTTP request, pages and retries included, in a `DelegatingHandler`. A request that waits longer than `ManagementApiOptions.QueueTimeout` fails with `ManagementApi.RateLimited`.

**Testing Tenant:** the Tenant tests run only locally and on pushes to `main`, never in PR runs, and each cleanup restores a fixed baseline on the target User. That keeps concurrent CI runs from racing on the one shared Tenant, as the owner decided.

**Role limits:** Auth0's reference states no length limit for a Role's name or description, so the spec sets its own, which the owner confirmed: a name of 1 to 100 characters, and a description of up to 500.
