# chore(scripts): Skip Sandcastle's own comments in watch-pr.sh

- **Release tag:** `v0.0.23`
- **Source PR:** [#72](https://github.com/mpaulosky/auth0-management-app/pull/72)

## PR description

### Why

`scripts/watch-pr.sh` tells the owner's comments from a Claude session's by the <code>&#60;&#33;&#45;&#45; claude&#45;session &#45;&#45;&#62;</code> marker, because the session posts with the owner's token. Sandcastle posts with the same token. So every Sandcastle follow-up report and hand-back on a watched PR woke the watcher as "new feedback", although none of it needs the session. On #69 and #70 that woke the watcher for seven comments with nothing to act on.

### What changed

- `watch-pr.sh` skips a PR comment, review body or review-thread reply that opens with a Sandcastle marker. It matches the anchored regex <code>&#94;&#60;&#33;&#45;&#45; sandcastle&#58;&#91;a&#45;z&#45;&#93;&#43; &#45;&#45;&#62;</code>, so a review that only quotes a marker, as reviews of Sandcastle's code do, still wakes the session.
- Two Sandcastle PR comments carried no marker, and now open with one:
  - The follow-up pass's hand-back ("Sandcastle stopped its follow-up passes on this PR…") opens with `GIVE_UP_MARKER`, <code>&#60;&#33;&#45;&#45; sandcastle&#58;give&#45;up &#45;&#45;&#62;</code>. It's a separate marker from `FOLLOW_UP_MARKER`, so it isn't counted as a follow-up pass.
  - The comment a pass posts when it leaves a tampered worktree opens with `WORKTREE_TAMPERED_MARKER`, <code>&#60;&#33;&#45;&#45; sandcastle&#58;worktree&#45;tampered &#45;&#45;&#62;</code>.
  
  Those, the pass summary (`FOLLOW_UP_MARKER`) and thread replies (`FOLLOW_UP_REPLY_MARKER`) are all the PR comments the host posts.

### Verification

- `pnpm run check:sandcastle`: 1,538 tests pass. New tests check that the hand-back comment opens with its marker and doesn't carry `FOLLOW_UP_MARKER`, and that a pass with worktree problems posts a comment opening with `WORKTREE_TAMPERED_MARKER`.
- `config.test.mts` reads `SANDCASTLE_MARKER` from `watch-pr.sh`. It checks that the regex is anchored, matches every <code>&#60;&#33;&#45;&#45; sandcastle&#58;</code> constant in `config.mts` at the start of a comment, and doesn't match a comment that only quotes one. So a new marker the watcher wouldn't skip fails the Sandcastle check.
- `shellcheck scripts/watch-pr.sh` is clean, and `scripts/gate.sh` passed on push.
- I ran the old and new comment filters against #69's live comments. The old filter reports four Sandcastle comments. The new one reports only the hand-back notice, which was posted before the marker existed.
- I checked the regex with jq: a body opening with a marker is skipped, and a review that quotes one mid-sentence is still reported.
