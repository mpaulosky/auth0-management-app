# feat(ManagementApi): Add the Management API seam

- **Release tag:** `v0.0.12`
- **Source PR:** [#47](https://github.com/mpaulosky/auth0-management-app/pull/47)

## PR description

Closes #32

### Why

The Users and Roles pages that are coming next need to read and change the Tenant's Users and Roles through Auth0's Management API.
Issue #32 adds the one seam they will call, `IManagementApi`, as specified in `docs/plans/user-role-management.md` and recorded in ADR 0009.
The SDK, the cached client-credentials token, the `Auth0:Management:*` settings and a client-side rate limiter all sit behind that interface.
Handlers get our own records and a `Result` with a stable error code, and never touch an SDK type.
No page or slice uses the seam yet, so Admins and Visitors see no change in this Release.

### What changed

- `Auth0.ManagementApi` 10.5.0 is added to `Directory.Packages.props` and referenced by `src/UI`. It's the Management API SDK the spec chose.
  Two test-only packages are added to `UI.Tests.Unit`:
  - `Microsoft.Extensions.Diagnostics.Testing`, for `FakeLogger`, to check what the seam logs.
  - `Microsoft.Extensions.TimeProvider.Testing`, for `FakeTimeProvider`, to drive the rate-limit message.
- `ResultErrorCode` gains `RateLimited = 6` in the Shared Kernel.
- `src/UI/ManagementApi/` (`UI.ManagementApi`) holds:
  - the public `IManagementApi` with its ten methods, the `ProfileField` flags enum and `AddManagementApi()`;
  - the public records `UserSearch`, `UserPage`, `UserSummary`, `UserDetails`, `ProfileFieldsChange`, `RoleSummary`, `NewRole` and `RoleMembers`;
  - the internal `ManagementApiAdapter`, which builds a `ManagementClient` for each call (one retry, a 10 s timeout) and pages through results.
    It maps Auth0's status codes to the catalogue's error codes and works out `EditableFields` from the User's identity.
    It logs, then throws, a failed token exchange, a 401 or 403, a timeout or any code the catalogue doesn't list;
  - the internal `ManagementApiError`, which holds the catalogue's codes, categories and messages, including "Auth0 is rate limiting the app. Try again in N seconds.";
  - the internal `ManagementApiOptions`, bound from `Auth0:Management` and validated on start;
  - the internal `RateLimitingHandler`, which takes one token from a singleton `TokenBucketRateLimiter` for each `/api/v2/*` request.
    It answers with its own 429 after `QueueTimeout` or when the queue is full;
  - the internal `RateLimitMark`, which flows with each call and lets an SDK timeout, or a 5xx after a 429, end as `ManagementApi.RateLimited` instead of throwing.
- `AddManagementApi()` registers its services with `TryAdd*`. It adds the options binding and the client's handler only once, so calling it twice doesn't stack a second limiter.
- The spec leaves three choices open, and the branch makes them as follows:
  - Offset listings stop once Auth0's total has been seen, which saves one empty-page request.
  - The bucket refills one token every 1/`PermitsPerSecond` seconds.
  - A 404 on assigning or removing a Role counts as `Role.NotFound` when Auth0's message mentions a role.
- The UI integration, AppHost integration and E2E setups supply placeholder `Auth0:Management:*` settings.
- `CLAUDE.md` says the seam exists and that no slice registers it yet.
- `.sandcastle/work/32/` had no design note, so there was none to follow or depart from.

### Verification

- `tests/UI.Tests.Unit/ManagementApi/` drives `AddManagementApi()` through a stub handler on the `"Auth0Management"` client:
  - `SearchUsersTests`: the query parameters sent, and Auth0's real total.
  - `GetUserTests`: the Profile Fields, connection, last login and Roles, and `EditableFields` for each connection type.
  - `UpdateProfileFieldsTests`: a field left alone is left out of the body, an empty string is sent as `null`, and an email change is sent unverified with no verification email.
  - `RoleCallsTests`: assigning, removing, listing and creating Roles.
  - `RoleMembersTests`: checkpoint paging, the 1000-member cap with `Truncated`, and a 429 partway through a listing.
    It also covers `CountRoleMembersAsync` stopping at `atMost`, and `UserHoldsRoleAsync` paging through every page.
  - `ErrorMappingTests`: every catalogue mapping, a 429 on every use case, a 5xx after a 429 returning `RateLimited` (added in review), and a status the catalogue doesn't list throwing.
  - `RateLimiterTests`: one token per request, retries included, and none for the token exchange.
    It also covers pacing with a limiter replenished by hand, the limiter's own 429 on a queue timeout or a full queue, both attempts timing out, and an unmarked timeout throwing.
  - `RateLimitedMessageTests`: N seconds counted against `FakeTimeProvider`, at least 1, and "a few seconds" when there's no reset header.
  - `FailureLoggingTests`: Error logs, with the settings hint for a failed token exchange and for a 403. No log line ever holds the access token or the client secret.
  - `ManagementApiRegistrationTests`: options validation, defaults, and calling the registration twice.
- `tests/Domain.Tests.Unit/Abstractions/ResultErrorCodeTests.cs` checks that `RateLimited` is 6.
- `tests/Architecture.Tests/ManagementApiTests.cs` checks that `UI.ManagementApi` depends on no slice and that only it references the SDK.
  It checks that its public types expose no SDK type and are exactly the expected set, that `IManagementApi` has the ten methods, and that `src/UI` has no `InternalsVisibleTo`.
  `PublicApiExposureRuleTests` shows that the exposure rule fails on a violation.
- `scripts/gate.sh` passed on the final branch:
  - lint of the one changed Markdown file;
  - the Release build;
  - every test project: Architecture 137, Domain 32, UI unit 516, UI integration 89, AppHost integration 5, and E2E 15 passed with 1 skipped (the one that needs a reachable Auth0 tenant).
