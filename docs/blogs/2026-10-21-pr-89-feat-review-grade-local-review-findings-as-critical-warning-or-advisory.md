# feat(review): Grade local review findings as Critical, Warning or Advisory

- **Release tag:** `v0.0.29`
- **Source PR:** [#89](https://github.com/mpaulosky/auth0-management-app/pull/89)

## PR description

### Why

The local review treated every finding alike, so a stale comment blocked a push as hard as a bug, and each round reviewed
the whole branch again. Issue #83 grades findings Critical, Warning or Advisory, so only bugs and security weaknesses
block, and later rounds review only the fixes.

### What changed

- **Severities.** Critical: bugs in code that runs (`src/`, `tests/`, the tooling), fixed in the review behind a test.
  Warning: security weaknesses in any file, which the person fixes or accepts. Advisory: docs, comments, prompts and
  conventions, which never block and are fixed in the review too; one left for a person goes to one follow-up issue per
  branch (#88 for this one). Critical also covers build and dependency configuration and new or changed behaviour with
  no test.
- **The ledger** (`.sandcastle/lib/review-ledger.mts`) stores each finding's severity and suggested fix. Older ledgers
  still parse, with a finding that has no severity counted as a Warning. `check` blocks only on open Critical and Warning
  findings, `report` groups by severity, and one `isSecurity` helper decides the `(security)` mark in both the report
  and the Review notes. The notes keep counting accepted security findings.
- **<code>prepare &#60;run&#62; &#60;since&#62;</code>** writes `fixes.patch` for a later round, refusing a `since` that isn't an ancestor of HEAD,
  is later than the round before, or sits on the far side of a merge of `main`.
- **`advisory`** prints the follow-up issue's body through the same plain-text rendering as the notes, leaving out any
  security finding. Every recorded finding needs an explicit `security` decision, and a missing one counts as security.
  Step 9 shows the person the exact text and posts it only once they say to.
- **The skill** (`/pre-push-review`) grades every finding, fixes Critical and Advisory ones (and the Warnings the person asks
  for), reviews again only after a round that fixed something (the last round only reviews), and records each lesson
  GitHub's Claude Review teaches. Its reviewers run on Opus.
- **A gate check that every gh command is told its repository** (`.github/ci/gate-checks.sh`), the first lesson: from a
  fork's clone an untold gh command reaches the fork. A script exports `GH_REPO`, a skill writes it before each gh
  command, and `gh repo`'s subcommands, which ignore `GH_REPO`, name their repository. The Owned Baseline scripts are left
  out; the Template's side is mpaulosky/dotfiles#267. The check reads quotes, escapes, comments and a `--repo`/`-R`
  after the subcommand, and the sandbox installs gawk for it. `scripts/watch-pr.sh` exports `GH_REPO` (and `WATCH_PR_REPO`
  overrides it).
- CLAUDE.md and `docs/CONTRIBUTING.md` describe the three severities, and say the uniform "Left for the owner." reply
  doesn't say which thread an accepted security finding is on, while the notes count them.

### Verification

- `pnpm run check:sandcastle`: tsc and all Sandcastle tests pass, including the new ledger, gate-check, skill and
  `watch-pr.sh` tests.
- `scripts/gate.sh` passed, review check included: the last local review run ended with every Critical and
  Warning finding fixed. Its final, review-only round raised five Advisory findings (tests and restated docs), added to #88.
