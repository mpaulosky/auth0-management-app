# fix(sandcastle): Let the critique see overlap-held issues, and don't fail the run on a comments read

- **Release tag:** `v0.0.178`
- **Source PR:** [#429](https://github.com/mpaulosky/Blazor-Server/pull/429)

## PR description

Closes #428

### Why

Sandcastle's overlap check holds back a pick that changes the same file as another pick or an open pull request. Two problems came out of the review of that check (#426).
First, the held issues no longer reached the critique at all: they weren't among the picks, and they were left out of the unpicked ready issues too.
The critique's dependency check is the safety net for a dependency the planner missed, so a pick that depended on a held issue could be built before the work it needs.
Second, the check read each deferred pick's comments before posting its deferral comment.
A failed read (one GitHub 5xx) escaped and ended the whole run, even though the deferral doesn't depend on that read.
Both affect anyone running Sandcastle unattended on this Template's issues.

### What changed

- `unpickedReady` (`.sandcastle/lib/plan.mts`) now takes the round's kept picks and the held issue numbers.
  It passes every ready issue that isn't a kept pick to the critique as unpicked, and gives each held one a `note` saying the overlap check held it back and it's still work to come.
- `main.mts` passes the round's overlap holds to `unpickedReady`, so a kept pick that depends on a held issue is deferred behind it.
- `critique-prompt.md` explains the `note`: a held issue was picked but held back, and it still counts for the dependency check.
- The shape of an unpicked issue with its optional note is one named type, `UnpickedIssue` in `lib/prompts.mts`, used by the critique, the plan and the prompt arguments.
- `deferOverlaps` (`.sandcastle/lib/overlap.mts`) still reads every deferred pick's comments before posting any, but a failed read now logs a warning and skips only that pick's comment.
  The pick is still deferred and reported, and the run carries on. A failed read of the open pull requests or their files still throws, so nothing is built on an overlap the host couldn't check.
- `docs/plans/sandcastle-workflow.md` describes both behaviours.

### Verification

- `.sandcastle/lib/plan.test.mts`: a held issue is passed as unpicked with a note saying it's held, an issue that isn't held carries no note, and a kept pick is never passed as unpicked.
- `.sandcastle/lib/critique.test.mts`: a held issue reaches the critique's `UNPICKED_JSON`, and a pick the critique defers behind it is dropped and linked as blocked by it.
- `.sandcastle/main.test.mts`: `main.mts` passes the round's holds to `unpickedReady`.
- `.sandcastle/lib/prompts.test.mts`: `critique-prompt.md` says an unpicked issue can be held back by the overlap check.
- `.sandcastle/lib/overlap.test.mts`: a 502 from the comments read doesn't throw, the pick is still held and reported as deferred, and a warning is logged.
  Only the failing pick's comment is skipped, and every pick's comments are still read before any comment is written. This replaces the test that expected the read to throw.
- `scripts/gate.sh` passed on the final branch: Markdown lint, the Sandcastle type-check and tests, the Release build and every .NET test project.
