# build(sandcastle): Install actionlint, shellcheck and zizmor in the sandbox image

- **Release tag:** `v0.0.96`
- **Source PR:** [#201](https://github.com/mpaulosky/Blazor-Server/pull/201)

## PR description

### Why

`scripts/gate.sh` runs actionlint, zizmor and shellcheck from `PATH` when they're installed, and otherwise through
Docker or `uvx`. The Sandcastle sandbox has neither, so in the sandbox the gate skipped all three with a warning. A
Sandcastle branch with a broken workflow or shell script passed both gate checkpoints, and the problem only showed up in
CI's lint checks.

### What changed

- `.sandcastle/Dockerfile` installs actionlint 1.7.12, shellcheck v0.11.0 and zizmor 1.30.1 into `/usr/local/bin`.
  These are the versions `gate.sh` pins. Each comes from the project's GitHub release, on amd64 or arm64, and the build
  fails unless the download matches its pinned SHA-256. The hashes match actionlint's published checksums file and the
  digests GitHub lists for the shellcheck and zizmor assets.
- New `.sandcastle/lib/dockerfile.test.mts`: checks that each version in the Dockerfile matches the one `gate.sh` pins,
  so a version bump in the gate (or a re-applied Baseline) can't leave the image behind.
- `.github/ci/gate-checks.sh` reruns the Sandcastle tests when `scripts/gate.sh` changes too. A Baseline Apply that bumps
  a linter version touches nothing under `.sandcastle/`, so without this the version test wouldn't run then.

### Verification

- Built the image (`docker build` with the host UID and GID) and, inside it, ran `actionlint`,
  `zizmor --offline --min-severity medium .` and `shellcheck scripts/*.sh` against this repository. All three passed.
- The new test passes, and it fails when the Dockerfile's zizmor version is changed to 1.30.0.
- The pre-push gate passed.

The existing Sandcastle image needs to be rebuilt after this merges.
