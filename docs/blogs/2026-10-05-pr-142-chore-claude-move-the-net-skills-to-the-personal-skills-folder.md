# chore(claude): Move the .NET skills to the personal skills folder

- **Release tag:** `v0.0.71`
- **Source PR:** [#142](https://github.com/mpaulosky/Blazor-Server/pull/142)

## PR description

### Why

The six `dotnet-*` skills were copied into `.claude/skills/` in this repo, as well as into the personal
`~/.claude/skills/` folder. Keeping one copy, the personal one, means there's only one place to update them, and they
stay available to Claude Code in every repo.

### What changed

- Deletes the `dotnet-*` skills from `.claude/skills/`, along with the markdownlint config that skipped them. The
  `code-review` skill stays: it's this template's own checklist, and `.github/copilot-instructions.md` is still
  generated from it.
- Removes the command allow list from `.claude/settings.json`. The deny rules that keep agents from reading or editing
  `.env` files stay, as `docs/SECURITY.md` documents.
- Sandcastle's Docker sandbox only mounts the worktree, so it can't see `~/.claude/skills`. A new
  `.sandcastle/lib/skills.mts` mounts the six `dotnet-*` skills read only into the agent's `~/.claude/skills`, and the
  planner, critique and build roles all use it. Each skill is mounted from its real path, because the entries in
  `~/.claude/skills` can be symlinks, which Docker wouldn't follow inside a mounted folder. A skill that's missing on the
  host is reported once and skipped. `implement-prompt.md` still tells the agent to use these skills.
- The sandbox image creates `~/.claude/skills` as the agent user. Otherwise Docker would create `~/.claude` as root for
  the mounts, and Claude Code couldn't write its config there.
- `.claude/rules/markdown.md` no longer mentions vendored skills in `.claude/skills/`.

### Verification

- `scripts/gate.sh` passed in the pre-push hook: the Markdown lint and the Sandcastle check (105 tests passed, two of
  them new tests for `skillMounts`), a Release build with 0 warnings and 0 errors, `Architecture.Tests` (4 passed) and
  `Domain.Tests.Unit` (29 passed).
- `scripts/sync-copilot-review.sh --check` passes.
- Rebuilt the sandbox image. In a sandbox created through `agentSandbox()`, all six skills are under
  `~/.claude/skills` and are read only, `~/.claude` stays writable by the agent, and `claude -p` lists the six
  `dotnet-*` skills among its available skills.
