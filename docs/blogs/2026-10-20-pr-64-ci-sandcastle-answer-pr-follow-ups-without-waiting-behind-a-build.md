# ci(sandcastle): Answer PR follow-ups without waiting behind a build

- **Release tag:** `v0.0.19`
- **Source PR:** [#64](https://github.com/mpaulosky/auth0-management-app/pull/64)

## PR description

Closes #53

### Why

When a Copilot review, a CI result or a Claude Review result lands on an open Sandcastle PR while an issue build is running, the follow-up run it starts waits in the job's single `sandcastle` concurrency group until the build run finishes, which can take hours.
Until then the PR sits with unresolved threads or a red check, and PR Auto-Merge holds it.
The workflow side, which landed switched off in #60, can now start these runs in their own `sandcastle-follow-up` group with `SANDCASTLE_MODE=follow-up`.
This change is the host side of that contract, so a follow-up run can answer a PR within minutes, beside a build, without the two runs working on the same PR.

### What changed

- **Run mode.** `runModeFrom` in `.sandcastle/lib/config.mts` reads `SANDCASTLE_MODE`: empty or unset is a full run, `follow-up` is a follow-up run, and any other value stops the run with exit code 2 and a message naming the variable and the value.
  It doesn't touch git, `gh` or a sandbox first.
  `main.mts` reads the mode right after the queue scope and the time budget, and logs it.
- **Follow-up-only runs.** The new `.sandcastle/lib/follow-up-run.mts` (`followUpOnlyRun`) does one sweep and the follow-up passes it finds, then exits.
  It runs no umbrellas, intake, gate, plan, builds or second round.
  `main.mts` calls it after the usual startup and runs the round loop only in a full run, so the run report and exit code work the same in both modes.
- **Overlap guard: `sandcastle:building`.** A pass already claims this label on a PR's issue before it touches the PR, and a build claims it on its issue.
  The sweep now skips any PR whose issue carries the label (matched case-insensitively), so neither run updates the branch of, re-requests Copilot on, relabels or passes on a PR the other run is working on.
  A full run now releases any label it still holds before its sweep, not after, so it never skips its own PR.
- **Closed-PR hand-backs only in full runs.** `sweepPullRequests` takes a new `handBackClosed` parameter, true by default.
  A follow-up run passes false, so a full run and a follow-up run can't both hand back one issue and post two comments.
- **The job's own check is ignored in every mode.** The sweep's query and the passes' head-check query now select each check run's workflow name.
  `openPullRequestsForSweep` and `headChecksOf` in `.sandcastle/lib/github.mts` drop check runs of the `Sandcastle` workflow (`SANDCASTLE_WORKFLOW`, kept in step with the workflow's `name:`).
  That drops the job's own check, the **Choose the run mode** job and a run GitHub cancelled in its concurrency group, so the sweep no longer waits on its own running check or flags a red one no pass can fix.
  A check another workflow names `Sandcastle`, a check with no workflow run (such as CodeQL) and every status context are kept.
  Truncation is still read before the filter.
- **Docs.** `docs/plans/sandcastle-workflow.md` describes follow-up runs, the overlap guard and its two known gaps (the label claim's one-round-trip race, and a follow-up event dropped when the full run holds the PR), full-run-only hand-backs and how the own check is left out.
  `.sandcastle/.env.example` and the `main.mts` usage note show `SANDCASTLE_MODE=follow-up`.
- **Departure from the design note:** the follow-up run's sweep passes a fresh set of PRs known to have carried `review:claude` rather than the module's run-long set.
  A follow-up run sweeps only once, so the two behave the same, and the set stays private to `lib/follow-up.mts`.

The host now supports the mode, so the owner can set the repository variable `SANDCASTLE_FOLLOW_UP_JOB=true` to turn follow-up runs on.
No mount, sandbox provider or host git setup changed, so this doesn't need a real-sandbox run before merging.

### Verification

- `.sandcastle/lib/config.test.mts`: `runModeFrom` returns a full run for unset and empty values and a follow-up run for `follow-up`.
  It throws `RunModeError` naming `SANDCASTLE_MODE` and the value for `full`, `Follow-up`, padded values and `build`.
  Another test checks that `SANDCASTLE_WORKFLOW` matches the `name:` of `.github/workflows/sandcastle.yml`.
- `.sandcastle/lib/follow-up-run.test.mts` (new): `followUpOnlyRun` sweeps once, then fetches main, reads the queue and runs the passes, with the sweep's targets passed through.
  When no PR needs a pass it logs a line and fetches nothing.
  An `UncountedStopError` from the passes propagates, and failed pass outcomes still resolve.
- `.sandcastle/lib/follow-up.test.mts`: `sweepSkipReason` names `sandcastle:building` when the PR's issue holds it.
  `sweepPullRequests` makes no write for such a PR, in either label case, and leaves it out of the passes and the waiting list, while still deciding other PRs.
  With `handBackClosed` false it neither reads closed PRs nor hands an issue back, but still sweeps open PRs.
- `.sandcastle/lib/github.test.mts`: both readers drop the `Sandcastle` workflow's checks (running, queued, red, cancelled, and the mode job) and keep every other kind listed above.
  They still report truncation, keep each check's Actions run ID, and both queries select the workflow name.
- `.sandcastle/main.test.mts`: the mode is read before `protectHostGit()` and `ensureHostLabels()`, and a spawned `main.mts` with `SANDCASTLE_MODE=bogus` exits non-zero, naming the variable and the value, without calling `gh`, `git` or `docker`.
  `followUpOnlyRun()` runs after startup and before the round loop, and the loop's condition reads the mode.
  `.env.example` mentions `SANDCASTLE_MODE` only in comments.
- `.sandcastle/lib/building.test.mts`: a full run releases its own building labels before the round's sweep.
- The tester's tests were not changed after they were committed red.
  `scripts/gate.sh` passed on the final branch: Markdown lint, the Sandcastle TypeScript check (type-check and every test), the Release build and every .NET test project.
