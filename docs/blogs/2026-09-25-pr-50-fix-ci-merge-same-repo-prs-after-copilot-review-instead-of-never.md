## fix(ci): Merge same-repo PRs after Copilot review instead of never

- **Release tag:** `v0.0.43`
- **Source PR:** [#50](https://github.com/mpaulosky/Blazor-Server/pull/50)

### PR description

## Summary

`pr-automerge.yml` never merged a PR:

- It waited until a PR was `CLEAN` and then asked GitHub to turn on auto-merge. GitHub always refuses that for a `CLEAN` PR ("Pull request is in clean status"), so the job failed every time (for example, on #48).
- For `status` events it read `context.payload.status`, a key that doesn't exist, so those events never matched a PR.
- GitHub sends no `check_suite` events for GitHub Actions suites, and every required check comes from Actions, so CI finishing never re-ran the job.

It now squash-merges a same-repo PR into `main` directly, once:

- required checks pass and the branch is up to date (`mergeStateStatus` is `CLEAN`),
- Copilot has reviewed the current head commit (it re-reviews merge-from-main updates too), and
- every review thread is resolved. A PR with more than 100 threads is left for a manual merge rather than checked from a partial page.

It re-checks on `pull_request` and `pull_request_review` events and when a CI workflow completes (`workflow_run` for Build and Test Suite, Lint Markdown, Lint YAML, CodeQL). Resolving a thread has no Actions trigger, so a 15-minute `schedule` (and `workflow_dispatch`) sweeps every open PR into `main`. The merge is pinned to the head SHA it checked. It merges with `RELEASE_PR_PAT`, because a `GITHUB_TOKEN` merge would not trigger `release.yml`; without the PAT it logs a warning.

PRs that already have auto-merge on (the release and backfill docs PRs) are left for GitHub to finish.

Also restores the original "Approve and run" wording in the `RELEASE_PR_PAT` notices in `release.yml` and `backfill-blog-posts.yml`. #48 changed it on a wrong premise: GitHub does create `pull_request` runs for `GITHUB_TOKEN` pushes, but they need approval.

## Validation

- `yamllint` and `node --check` on the embedded script
- The script run against mocked GitHub responses in 15 scenarios (ready, no Copilot review, review of an older commit, unreviewed merge-from-main head, reviewed merge commit, unresolved thread, more than 100 threads, checks pending, behind main, auto-merge already on, fork PR, `workflow_run`, scheduled sweep across several PRs, head moved mid-merge, no PAT)
- The pre-push hook passed YAML lint, Markdown lint and the full test suite

Not yet exercised against real GitHub events. This PR's own `pull_request` events run the new script, so it may merge itself once Copilot has reviewed it and its threads are resolved. The `schedule` and `workflow_run` triggers only take effect once this is on `main`.
