# docs: Describe the app as an Auth0 User and Role manager

- **Release tag:** `v0.0.3`
- **Source PR:** [#7](https://github.com/mpaulosky/auth0-management-app/pull/7)

## PR description

### Why

This repo began from a GitHub template, but it's its own app: an Admin uses it to manage the Users and Roles of one Auth0 Tenant.
The docs, the domain language and the Home page still described it as a Template that produces a Generated App.

### What changed

- **README:** describes what the app does: list Users, edit their Profile Fields, add and remove Roles, create Roles.
  It also says what the app never does: change passwords or usernames, create or delete Users.
  It keeps the sign-in setup, adds a Management API section (a Machine to Machine application, its six permissions and the `Auth0:Management:*` settings),
  and drops "Use this template" and "After generating your app".
- **CONTEXT.md:** drops Template and Generated App. Adds Tenant, Management API, Role and Profile Fields, and widens User to anyone in the Tenant.
- **CLAUDE.md:** a new intro, plus an "Auth0 Management API" section of rules for the upcoming slice, modelled on the Articles repo's `UserManagement` feature.
- **Home page:** the eyebrow is now `Admin tool` and the badge `Projects`, and the lead describes managing Users and Roles. `HomePageTests` changes with it.
- **Wording:** doc comments, the code-review skill (with `.github/copilot-instructions.md` re-synced), the Sandcastle prompts,
  `src/Domain/README.md` and `docs/CONTRIBUTING.md` say "the app" instead of Template or Generated App.
  `ReleaseDomainTermTests` follows the reworded Release entry.
- **Left as they were:** the ADRs and `docs/plans/`, which record past decisions.

User and Role management isn't built yet. The README marks it as planned.
