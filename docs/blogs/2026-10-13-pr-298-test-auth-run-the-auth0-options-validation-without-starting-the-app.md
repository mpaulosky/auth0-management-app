# test(auth): Run the Auth0 options validation without starting the app

- **Release tag:** `v0.0.137`
- **Source PR:** [#298](https://github.com/mpaulosky/Blazor-Server/pull/298)

## PR description

### Why

`OptionsValidationTests` failed on PR #295's CI with an `ObjectDisposedException` instead of the expected `OptionsValidationException`. A rerun passed, so the test is flaky.

The cause is a race in `WebApplicationFactory` when the app fails to start:

- The app's entry point runs `app.Run()` on its own thread. `ValidateOnStart` throws there, and the entry point disposes the host.
- Meanwhile, `DeferredHost.StartAsync` asks that host's service provider for `IHostApplicationLifetime`.

When the disposal wins, the caller gets `ObjectDisposedException: Cannot access a disposed object. Object name: 'IServiceProvider'`, which has no inner exception, so the validation error is lost.

### What changed

- `OptionsValidationTests` no longer starts the app.
  - Each test registers the Authentication feature (`AddAuthenticationFeature`) over the factory's placeholder Auth0 settings, with one setting replaced.
  - It then runs `IStartupValidator.Validate()`, the check the host runs for `ValidateOnStart`.
  - The cases are the same as before: a missing Domain, ClientId or ClientSecret, a whitespace ClientSecret, and a Domain that isn't a host. Each test checks that the error names the setting.
- New `ValidateOnStart_EveryAuth0SettingValid_DoesNotThrow`, so the helper's baseline settings are known to be valid.
- A comment at the top of the class records why the tests don't go through `WebApplicationFactory`.

`Program.cs` still calls `AddAuthenticationFeature`, and every other integration test that signs in depends on that, so starting the host isn't needed to cover the wiring.

### Verification

- `UI.Tests.Integration`: 58 passed.
- With `.ValidateOnStart()` temporarily removed from `AuthenticationFeature`, 7 of these tests fail, so they still catch a missing validation.
- The pre-push gate passed.
