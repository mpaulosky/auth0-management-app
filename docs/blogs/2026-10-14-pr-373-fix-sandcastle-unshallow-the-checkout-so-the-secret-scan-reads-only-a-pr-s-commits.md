# fix(sandcastle): Unshallow the checkout so the secret scan reads only a PR's commits

- **Release tag:** `v0.0.159`
- **Source PR:** [#373](https://github.com/mpaulosky/Blazor-Server/pull/373)

## PR description

### Why

Sandcastle's follow-up pass on [#372](https://github.com/mpaulosky/Blazor-Server/pull/372) was handed back as a secret leak, and nothing was pushed. The "secret" was `github_pat_example_placeholder_value_goes_…`, a deliberately fake token in `.github/scripts/tests/test_post_claude_review.py` that has been on `main` since #176.

The scan should only have read #372's own commits. Before a push it scans <code>main&#46;&#46;&#60;gated commit&#62;</code>, but the workflow checks out `main` at `actions/checkout`'s default depth of 1, and nothing deepened it. In a shallow clone git can't see that a branch's older history is already in `main`, so the range lists everything the branch reaches past the cut: **280 commits** on #372, against **6** in a full clone.

It only shows once `main` has moved past the branch's base. #370's pass got through because `main` hadn't moved yet. Left alone, it hands back every follow-up pass on a branch that's behind `main`, including the three Theme and Palette PRs still to come.

### What changed

- **`.sandcastle/lib/branches.mts`:** `fetchMain` asks `git rev-parse --is-shallow-repository`, and in a shallow checkout fetches `main` with `--unshallow`. Git refuses `--unshallow` in a full clone, so a full clone fetches as before. `fetchMain` also takes git as a parameter with a live default, as `forgetGatedHead` does, so tests can stub it.
- **`.sandcastle/lib/branches.test.mts`:** two tests pin the fetch: `--unshallow` for a shallow checkout, and the plain fetch for a full clone.

The fix sits in `fetchMain` rather than in `sandcastle.yml` (`fetch-depth: 0`) because the Baseline owns the workflow files. It also keeps the scan's range right wherever Sandcastle runs. Both follow-up passes and builds take their base from `fetchMain`, so both are covered.

### Verification

- `pnpm run check:sandcastle`: the type-check and all 1090 tests pass. The two new tests failed before the change.
- The real git command, run against this repo: in a fresh `--depth 1` clone of `main` with #372's branch fetched, `main..` the branch counted **280** commits. After `git fetch --quiet --unshallow origin +refs/heads/main:refs/remotes/origin/main`, the same count was **6** and the repository was no longer shallow.
- The pre-push gate passed.

**Needs a real run:** this changes how the host runs git, and the shallow case only exists in the GitHub Actions run. That run checks out `main`, so it can't exercise this branch before it merges. The first Sandcastle run after the merge is the real check: its follow-up pass on a branch that's behind `main` should push instead of handing back.
