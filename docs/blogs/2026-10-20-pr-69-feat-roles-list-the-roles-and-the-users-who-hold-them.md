# feat(Roles): List the Roles and the Users who hold them

- **Release tag:** `v0.0.22`
- **Source PR:** [#69](https://github.com/mpaulosky/auth0-management-app/pull/69)

## PR description

Closes #39

### Why

An Admin couldn't see which Users hold which Roles.
The Auth0 dashboard shows one Role's members at a time, and this app had no Roles page.
This branch adds `/admin/roles`, the first page built on the Management API seam.
It shows every Role in the Tenant as a tile with its member count, and a User table with a column per Role.
Picking a tile filters the table to that Role's members.

### What changed

- The Roles slice in `src/UI/Components/Features/Roles/`:
  - `GetRolesOverviewQuery` and `GetRolesOverviewHandler` read the content. The handler lists the Roles, then each Role's members one call at a time.
    With no Role picked, the table is the first page of the User search: page 1, 25 Users, the Users page's size.
    With a Role picked, the table is that Role's members.
    Each row marks every Role as held, not held, or unknown. Unknown is for a User missing from a `Truncated` Role's first 1,000 members.
    A Management API failure comes back unchanged. A picked Role that isn't in the Role list fails with `Role.NotFound`.
  - `RolesOverview.cs` holds the result records `RolesOverview`, `RoleTile`, `RoleUserRow` and `RoleHolding`.
  - `RolesPage.razor` is `/admin/roles`. It renders with `@rendermode InteractiveServer` and requires the Admin policy.
    It holds the page header, its own **Users | Roles** tab switch (two plain links) and `ManagementApiErrorBoundary`.
    It reads `?role=` from the URL.
  - `RolesContent.razor` is the boundary's child, so an exception thrown after an await still reaches the boundary.
    It renders the tiles and the table. A tile shows "1,000+" for a `Truncated` Role.
    A held Role shows a check. An unknown one shows "?", titled "Unknown: more than 1,000 Users hold this Role".
    Each User links to <code>&#47;admin&#47;users&#63;user&#61;&#123;id&#125;</code>.
    Picking a tile reloads the table and writes <code>role&#61;&#123;id&#125;</code> with `history.replaceState`. Picking the same tile again clears the filter.
    A Truncated pick shows "Showing the first 1,000 Users who hold {Role}."
    A failure shows in place of the tiles and the table: a Warning `Alert` for a rate limit, an Error `Alert` for anything else, such as "This Role no longer exists in the Tenant."
  - `AddRolesFeature()` calls `AddManagementApi()` and registers the handler as a singleton. `Program.cs` calls it.
- `src/AppHost/AppHost.cs` passes `Auth0:Management:Domain`, `:ClientId` and `:ClientSecret` (marked secret) to `WebApp` as `Auth0__Management__*`.
  The seam validates these settings on start, so `WebApp` stopped at startup under the AppHost without them.
  `README.md` says `aspire run` passes them.
- `tests/UI.Tests.Integration` gains an NSubstitute package reference, already in `Directory.Packages.props`, to substitute `IManagementApi`.
- A refactor commit builds each tile in the members loop instead of matching two lists by index afterwards.
  It also removes a failure branch in `RolesContent` that could never render, and replaces a nested ternary with an if chain.

There was no design note for this issue.
