# feat(sandcastle): Label each PR Sandcastle opens review:claude

- **Release tag:** `v0.0.13`
- **Source PR:** [#45](https://github.com/mpaulosky/auth0-management-app/pull/45)

## PR description

### Why

Claude reviews a PR only when it has the `review:claude` label. `CLAUDE.md` told whoever was watching a Sandcastle run to add it by hand to each PR the run opened. That made the owner a manual step in an otherwise unattended pipeline, and a PR nobody was watching went without a Claude review.

### What changed

- `openPullRequest` in `.sandcastle/lib/github.mts` adds `review:claude` straight after it creates a PR. The label name is `REVIEW_LABEL` in `lib/config.mts`.
- A PR the host finds already open for the branch gets the label only if its label events show it never carried it. That covers a create GitHub carried out but answered with an error, and a run that stopped before the label went on. PR Auto-Merge removes `review:claude` once the review cap is reached, so a PR it took the label off stays unlabelled and the cap holds.
- Labelling comes after the create, and a failure only warns, so a missing label never costs a finished build its PR. The run report (`summary.md` and the job summary) lists each PR the run couldn't label under **Pull requests without `review:claude`**.
- `docs/plans/sandcastle-workflow.md` describes this under **Labelling the PR**.
- `CLAUDE.md` now says Sandcastle labels its own PRs, and to add the label by hand only to a PR the run report lists.

### Verification

- New tests in `.sandcastle/lib/github.test.mts`:
  - a PR `openPullRequest` creates gets <code>gh pr edit &#60;n&#62; &#45;&#45;add&#45;label review&#58;claude</code>;
  - when that edit fails, the PR's URL is still returned and one warning names the label and the PR.
  - a reused PR that has never carried the label gets it; one whose label was taken off isn't relabelled; one that has it costs a single `gh` call;
  - a failed label add, and a failed read of a reused PR's label events, each go in the run report;
  - `renderSummary` lists those PRs, and leaves the section out when there are none.
- `pnpm run check:sandcastle` passes: the type-check and all 1,185 tests.
- markdownlint passes on `CLAUDE.md` and `docs/plans/sandcastle-workflow.md`, and the pre-push gate passed.
