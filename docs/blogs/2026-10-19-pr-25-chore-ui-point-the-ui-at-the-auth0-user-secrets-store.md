# chore(ui): Point the UI at the Auth0 user secrets store

- **Release tag:** `v0.0.9`
- **Source PR:** [#25](https://github.com/mpaulosky/auth0-management-app/pull/25)

## PR description

### Why

The UI project's `UserSecretsId` pointed at an old user secrets store. The Auth0 settings for local development live in a different one, so `dotnet run` didn't find them.

### What changed

- `src/UI/UI.csproj` now sets `UserSecretsId` to `94491f6e-auth0-values-3ff40da38702`, the store that holds the Auth0 settings.
- The store is shared on purpose with the maintainer's other Auth0 projects, so a `dotnet user-secrets set` in any of them changes it for all. The `Auth0:Management:*` values in it must be this app's own Machine to Machine application, granted only the permissions in `README.md`.
- A developer who stored secrets under the old ID (`786426a9-2984-4860-8484-790023527e28`) copies its `secrets.json` to the new ID's folder, or runs the `dotnet user-secrets set` commands in `README.md` again.

### Verification

- The pre-push gate passed: a Release build and every test project.
- No secret values are committed. The ID only names the local folder that holds them.
