# docs(ui): Add the Theme and Palette spec and ADR 0007

- **Release tag:** `v0.0.156`
- **Source PR:** [#368](https://github.com/mpaulosky/Blazor-Server/pull/368)

## PR description

### Why

The Theme and Palette map ([Map: Theme toggle and cookie, and the Palette picker](https://github.com/mpaulosky/Blazor-Server/issues/353)) has settled every decision the
Theme control and the Palette menu need. Sandcastle builds from issues that point at a spec, so the decisions need one document that says what to build.

### What changed

- **`docs/plans/theme-and-palette.md`**, the spec. It covers:
  - **Value types:** <code>Theme &#123; System&#44; Light&#44; Dark &#125;</code> and the 17-hue `Palette` (Blue default), with C# 14 `extension` blocks that parse the cookies forgivingly.
  - **The cookies:** one year, `SameSite=Lax`, `Secure`, `HttpOnly`, essential. Choosing System deletes the theme cookie, and choosing Blue writes `blue`.
  - **Reading and writing:** `App.razor` renders `data-theme` and `data-palette` from the cookies. `POST /theme` and `POST /palette` copy the Log out pattern, with
    FluentValidation behind pure handlers and a `400 ProblemDetails` for an unknown value.
  - **The controls,** from the prototype: a segmented Light/Dark/System group and a Palette menu of labelled swatch tiles, on desktop and in the mobile menu.
  - **The 16 Palette rules,** with the contrast research's darker stops for the nine bright hues, plus the **tests** and the five **implementation issues** in build order.

  Three choices go beyond the map's tickets:
  - **The slice folders are plural,** `Features/Themes/` and `Features/Palettes/`. A type named like its own namespace doesn't compile from a sibling namespace (CS0118 in
    the mirrored test namespace), and plural folders let the types keep the glossary names.
  - **Choosing a Palette closes the open menu and drops keyboard focus.** That's accepted for now, to keep the controls free of JavaScript.
  - **The cookie's year runs from the visitor's last choice.** It's re-issued on each choice, not on every request.
- **`docs/adr/0007-cross-cutting-code-outside-the-slices.md`:** code that more than one slice needs, and that isn't a component, lives in its own <code>src&#47;UI&#47;&#60;Concern&#62;&#47;</code> folder.
  The first is `UI.Security`, holding `LocalReturnUrl`.
- **`docs/CODING_STANDARDS.md`:** the slice example is `Features/Themes/`, with the plural-folder rule, and cross-cutting code goes to `Components/Shared/` or a
  <code>src&#47;UI&#47;&#60;Concern&#62;&#47;</code> folder.
- **`CONTEXT.md`:** the Theme has three states, Light, Dark and System, and choosing System again returns to following the OS.

### Verification

- `markdownlint-cli2` passes on the four files.
- The pre-push gate passed.
- A scratch project confirmed both naming points: the singular namespace fails with CS0118, and the static extension members (`Theme.FromCookie`, `Palette.Default`) compile.

No code changes. The class lists come from the prototype branch `chore/prototype-theme-palette`.
