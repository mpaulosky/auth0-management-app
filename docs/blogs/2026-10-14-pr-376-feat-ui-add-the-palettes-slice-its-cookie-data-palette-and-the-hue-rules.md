# feat(ui): Add the Palettes slice, its cookie, data-palette and the hue rules

- **Release tag:** `v0.0.160`
- **Source PR:** [#376](https://github.com/mpaulosky/Blazor-Server/pull/376)

## PR description

Closes #365

### Why

The Template's README roadmap promises a Palette: an accent colour the visitor picks at runtime and keeps in a cookie.
Until now the Generated App had no way to store that choice, render it or change the accent from it, so every app was blue.
This branch adds the server side of the Palettes slice: the value type, the endpoint that sets the `palette` cookie, the `data-palette` attribute on <code>&#60;html&#62;</code> and the CSS rules that swap the accent hue.
The menu a visitor clicks comes in the next issue, so nothing changes on screen yet unless a `palette` cookie is already set.

### What changed

- New slice `src/UI/Components/Features/Palettes/`, following `docs/plans/theme-and-palette.md`:
  - `Palette`, an enum of the 17 Tailwind hues in Tailwind's order (the gray family is left out).
  - `PaletteExtensions`, a C# 14 `extension(Palette)` block with `Default` (Blue), `FromCookie` (ordinal and case-sensitive, Blue for anything unknown),
    `ToCookieValue`, `ToDataPalette` (`null` for Blue) and `SwatchClass` (a literal <code>bg&#45;&#60;hue&#62;&#45;500</code> per hue, so the Tailwind scan finds all 17).
  - `SetPaletteCommand`, `SetPaletteCommandValidator` (accepts exactly the 17 lowercase names, error code `Palette.Unknown`, and a message that doesn't echo the posted value)
    and `SetPaletteHandler`, which returns a <code>Result&#60;Palette&#62;</code>.
  - `PaletteEndpoints`: `POST /palette` checks the antiforgery token itself, sets the `palette` cookie (one year, `SameSite=Lax`, `Secure`, `HttpOnly`, `Path=/`, essential) and answers 302 to `LocalReturnUrl.OrRoot(returnUrl)`.
    An unknown value answers 400 `application/problem+json` with `code: Palette.Unknown`, and a failed token redirects without setting a cookie.
    GET and HEAD answer 405 with `Allow: POST`, the same as Log out.
  - `PaletteFeature.AddPaletteFeature()` registers the validator and handler as singletons.
- `Program.cs` calls `AddPaletteFeature()` and `MapPaletteEndpoints()`.
- `Components/App.razor` renders `data-palette` on <code>&#60;html&#62;</code> from the cookie, and leaves it out for Blue, no cookie or an unknown value.
- `src/UI/Styles/app.tailwind.css` gets a <code>&#58;root&#91;data&#45;palette&#61;&#34;&#60;hue&#62;&#34;&#93;</code> rule in `@layer base` for each hue except Blue, setting all 11 accent stops.
  Orange, emerald, teal, cyan and sky map `accent-500`, `accent-600` and `accent-700` to their 600, 700 and 800 stops.
  Amber, yellow, lime and green map them to 700, 700 and 800, so white button text and the light-mode focus ring keep WCAG AA.
- `UI.csproj` references `FluentValidation`, which was already versioned in `Directory.Packages.props`.
  The plan chose it as the request validator the coding standards require.
  The handler takes the validator through its constructor, so the DependencyInjectionExtensions package isn't needed.
- A refactor commit gives the private static readonly fields PascalCase names, as the coding standards ask, and renames the endpoint's private `CookieOptions()` helper to `PaletteCookieOptions()`.

Issue #363's Themes slice isn't on this branch yet, so `App.razor` doesn't render `data-theme` here.
Each slice builds its own `CookieOptions`, as the plan says.

### Verification

- `tests/UI.Tests.Unit/Components/Features/Palettes/PaletteExtensionsTests.cs`: `FromCookie` for each of the 17 names, and Blue for `null`, `""`, `Rose`, `gray` and an unknown value.
  It also checks that `ToCookieValue` and `ToDataPalette` round-trip, that `ToDataPalette` is `null` for Blue, that `SwatchClass` returns <code>bg&#45;&#60;hue&#62;&#45;500</code> and that `Default` is Blue.
- `tests/UI.Tests.Unit/Components/Features/Palettes/SetPaletteCommandValidatorTests.cs`: the 17 names pass.
  `null`, `""`, `Rose`, `gray` and an unknown value fail with `Palette.Unknown`, and the message doesn't echo the posted value.
- `tests/UI.Tests.Unit/Components/Features/Palettes/SetPaletteHandlerTests.cs`: success returns the matching `Palette`.
  Failure returns `ResultErrorCode.Validation` with `Details` equal to `Palette.Unknown`.
- `tests/UI.Tests.Unit/Styles/AppTailwindCssTests.cs`: each hue except Blue has a rule setting all 11 stops, with the shifted hues mapped as the plan's table says, and Blue has no rule.
- `tests/UI.Tests.Integration/AppTests.cs`: a `palette=rose` cookie renders `data-palette="rose"`, and `blue`, no cookie and an unknown value render no attribute.
- `tests/UI.Tests.Integration/Components/Features/Palettes/PaletteEndpointTests.cs`: valid posts for rose and blue set the cookie with the plan's attributes and answer 302 to the `returnUrl`.
  It also checks that a non-local `returnUrl` redirects to `/`, an unknown value gets the 400 problem response with its code,
  a failed token redirects without a cookie, and GET answers 405 with `Allow: POST`.
- `tests/Architecture.Tests/UiTests.cs`: the slice rule finds Palettes and no cross-slice dependencies.
- `scripts/gate.sh` passed on the final branch: the lints, the Release build, and every test project, E2E included.
  One E2E test was skipped by design, because it needs a reachable Auth0 tenant.
