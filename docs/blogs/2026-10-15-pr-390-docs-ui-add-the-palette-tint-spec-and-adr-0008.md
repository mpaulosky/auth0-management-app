# docs(ui): Add the Palette tint spec and ADR 0008

- **Release tag:** `v0.0.163`
- **Source PR:** [#390](https://github.com/mpaulosky/Blazor-Server/pull/390)

## PR description

### Why

The visitor's Palette only coloured buttons, links and highlights, and every surface stayed slate. The map [Map: Tint the Generated App's surfaces with the Palette](https://github.com/mpaulosky/Blazor-Server/issues/382) settled that the Palette tints the page, cards, nav, footer, borders and hover fills too, in both Themes. A contrast check and two prototypes backed that decision. This PR is the spec Sandcastle builds from.

### What changed

- `docs/plans/palette-tint.md`: the spec, covering:
  - the surface-class mapping (raw `accent-*`, no new tokens) and the Palette menu exception;
  - the text and focus-ring shades that keep WCAG AA for all 17 hues;
  - the accent touches (title gradient, eyebrow, StatTile, Profile table header, browser chrome);
  - the architecture guard and the tests.
- `docs/adr/0008-the-palette-tints-the-surfaces.md`: why the Palette now tints surfaces, and the options rejected (slate `color-mix`, named surface tokens, slate surfaces, a Neutral Palette).
- `CONTEXT.md`: **Palette** is the hue that tints the accent and the surfaces; Theme still decides light or dark.
- `docs/CODING_STANDARDS.md` and `.claude/rules/blazor.md`: the surface, text and focus-ring rule.
- `docs/plans/ui-restyle.md` and `docs/plans/theme-and-palette.md`: pointers to the new spec.

The implementation issues are filed with native blocking. The owner adds `Sandcastle` once this merges.

- [feat(ui): Tint the surfaces with the Palette, and guard them](https://github.com/mpaulosky/Blazor-Server/issues/388)
- [feat(ui): Add the accent touches: the title gradient, StatTile, the Profile table header and the browser chrome](https://github.com/mpaulosky/Blazor-Server/issues/389), blocked by the first

### Verification

- Every text, link, focus-ring and touch pair in the spec was checked against all 17 hues in both Themes, using Tailwind 4.3.3's colour values and the research script. The spec's minimums come from that run. The three failing pairs it found were fixed before writing: Dark secondary text, the Profile table header, and the eyebrow.
- The final design was built as the spec writes it on the throwaway branch `chore/prototype-palette-tint` and reviewed in the browser.
- `markdownlint-cli2` passes, and `scripts/gate.sh` passed on push.
