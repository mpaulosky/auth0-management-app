# docs(README): Point the Releases table to how Releases are cut

- **Release tag:** `v0.0.28`
- **Source PR:** [#86](https://github.com/mpaulosky/auth0-management-app/pull/86)

## PR description

Closes #84

### Why

The **Releases** section near the top of `README.md` lists recent Releases in a table the release workflow generates.
It doesn't say how a Release is made.
That's explained further down, in **Releases and blog posts**, which a reader of the table had no pointer to.

### What changed

- `README.md`: one line after the `All releases →` link, outside the <code>&#60;&#33;&#45;&#45; RELEASES&#95;START &#45;&#45;&#62;</code> / <code>&#60;&#33;&#45;&#45; RELEASES&#95;END &#45;&#45;&#62;</code> block:
  <code>How Releases are cut&#58; see &#91;Releases and blog posts&#93;&#40;&#35;releases&#45;and&#45;blog&#45;posts&#41;&#46;</code>
  The release workflow (`.github/scripts/release_post.py`) replaces only the text between those markers, so the line survives each regeneration.
- `.sandcastle/readme.test.mts`: a new test file that pins where the line sits and that its link resolves.
  A follow-up refactor names the anchor once (`ANCHOR`) and builds the line from it, rather than parsing it back out with a regex, and finds the line once instead of in each test.
  Every assertion checks what it checked before.

There was no architect's design note for this issue.
