# fix(sandcastle): Close the design note's edge cases from #228's review

- **Release tag:** `v0.0.108`
- **Source PR:** [#232](https://github.com/mpaulosky/Blazor-Server/pull/232)

## PR description

### Why

#228 merged at the owner's request with four findings from Claude's review of its final push still open (#230). They are
edge cases in the architect's design note (`.sandcastle/lib/build.mts`):

- **A stale note:** <code>&#46;sandcastle&#47;work&#47;&#123;n&#125;&#47;design&#46;md</code> lives in a worktree named after the branch. An earlier round's note
  could steer a later round's tester, developers and reviewer, or be posted again as new when the architect didn't
  rewrite it.
- **An edited comment:** GitHub stores a comment edited on github.com with CRLF line endings, so `designNoteIn` couldn't
  find the fence, and the architect got the whole comment back with its <code>&#60;&#33;&#45;&#45;</code> still broken.
- **Comment length:** the 60,000-character cut came before each <code>&#60;&#33;&#45;&#45;</code> gained a character, so a note full of them could
  pass GitHub's 65,536-character limit. The cut could also split a surrogate pair. Either way GitHub refuses the
  comment.
- **Untested lookup:** nothing tested that the live `latestDesignNote` ignores a design comment from anyone but the
  host. Its result goes straight into the architect's prompt.

### What changed

- **Stale note:** `buildMarkedIssue` runs <code>rm &#45;f &#46;sandcastle&#47;work&#47;&#123;n&#125;&#47;design&#46;md</code> in the sandbox before the first role,
  so the note exists only when this build's architect wrote it. A round without the architect now runs with no design
  note. That's deliberate: an earlier round's note may be out of date, and the issue may have been rewritten since.
- **CRLF:** `designNoteIn` normalises line endings before matching the fence.
- **Length:** `designComment` breaks <code>&#60;&#33;&#45;&#45;</code> first, then measures and cuts. `cutAtCharacter` drops a trailing high
  surrogate.
- **Lookup:** `latestDesignNote` moved out of `liveHost` into an exported function that takes the repo, the gh runner and
  the poster, as `markerComments` does. `liveHost` calls it.

### Verification

- New tests, written first and seen failing:
  - The old note is removed before the first role runs, with or without the architect.
  - A comment with CRLF line endings reads back as the note.
  - A note of 16,000 <code>&#60;&#33;&#45;&#45;</code> gives a comment under the limit.
  - A cut that lands inside a surrogate pair leaves no lone surrogate.
  - `latestDesignNote` returns the host's note and ignores a later one from a stranger. It returns `undefined` when only
    a stranger has posted one.
- Mutation checks: each test goes red when I remove the code it covers. That covers the `rm`, the CRLF normalisation,
  cutting before breaking, the surrogate guard, and the poster filter.
- `pnpm run check:sandcastle` passes, and so does `scripts/gate.sh` on push.
